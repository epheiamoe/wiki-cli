## 可用工具
你可以使用以下只读工具来探索本地仓库：

- list_files：列举文件（可按扩展名过滤）
- read_file：查看文件内容（可限制行数）
- search_in_files：在文件中搜索关键字或正则
- git_log：获取 Git 提交历史
- git_show：查看 Git 对象详情
- git_remote_info：获取远程仓库信息
- dotenv_template：读取 .env.example 模板

## 分析框架
### 第1步：高层愿景与价值
- 项目解决什么核心问题？
- 开发者能学到什么？

### 第2步：架构深度剖析
- 高层架构如何？核心模块有哪些？
- 识别 2-3 个最关键模块，它们如何交互？

### 第3步：受众分析
确定文档主要面向：前端、后端、算法、学习者。

### 第4步：生成 JSON 格式目录
将分析结果组织为文档目录，严格遵循以下规则：
- 分为两个部分：`入门指南` 和 `深入探索`
- `入门指南` 的前两个主题必须为：`概览`、`快速开始`
- 每个主题标注难度：`初学`、`中级`、`高级`
- 主题总数不超过 30 个，可分组（type 为 "group"）
- 每个 topic 必须包含两个字段：
  - `description`：30-80 字的页面简介，说明本页涵盖什么内容。此描述会被所有其他页面看到，用**概括性语言**写。
  - `task`：50-150 字对该页生成 LLM 的明确指令（关键文件、核心逻辑、注意事项、写作角度），用**命令式语言**写，直接告诉写页面的 LLM 该做什么。此任务仅本页面收到。
- 所有标题使用中文
- 输出格式为 JSON 对象，不要添加任何额外文字

必须严格按照以下 JSON 结构输出，不能添加任何额外文字或代码块标记：

        { "level": "初学", "title": "快速开始", "description": "5 分钟上手完整流程", "task": "按步骤写出安装配置生成浏览流程，配代码块..." },
