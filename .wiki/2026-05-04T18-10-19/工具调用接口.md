# 工具调用接口

```mermaid
flowchart LR
    A[AI Agent CLI] -->|"tool-call <name> [args]"| B[参数解析]
    B --> C[工具名校验]
    C -->|非法| D[报错退出]
    C -->|合法| E[加载配置]
    E --> F[初始化 Embedding / Web Fetch]
    F --> G[解析 JSON 参数]
    G -->|JSON 不合法| H[报错退出]
    G -->|合法| I[executeToolCall]
    I --> J[{"type":"success/error","data":...}]
```

`tool-call` 命令是 wiki-cli 提供给外部 AI Agent 的**标准化只读工具接口**。它接收一个工具名和可选的 JSON 参数，执行后直接向标准输出打印 JSON 结果。整个调用链可以拆解为四个步骤：**工具名合法性校验** → **配置加载与环境初始化** → **参数 JSON 解析** → **工具分派执行**。

## 注册与参数结构

命令在 Commander.js 体系中注册为 `wiki-cli tool-call <name> [args]`：

```ts
program
  .command('tool-call')
  .description('Execute a tool and output JSON result (for AI agents)')
  .argument('<name>', 'Tool name')
  .argument('[args]', 'JSON arguments string')
```

`name` 是必选的位置参数，对应工具的函数名；`args` 是可选参数，预期是一个 JSON 字符串，如 `'{"path":".","extensions":[".ts"]}'`。注意 `args` 必须是一个完整的 JSON 对象字符串——传入后会被 `JSON.parse` 处理，不是 Commander 原生解析的键值对。

[来源](src/cli.ts#L146-L156)

## 工具名合法性校验

进入 `toolCallCommand` 后，第一件事是从 `toolDefinitions` 数组中查找匹配的工具：

```ts
const validTool = toolDefinitions.find(t => t.function.name === name);
if (!validTool) {
  logError(`Unknown tool: "${name}".\nAvailable tools:\n${names}`);
  process.exit(1);
}
```

`toolDefinitions` 是一个包含 13 个工具定义的数组，每个定义遵循 OpenAI Function Calling 的 JSON Schema 格式，包含 `type: 'function'`、`function.name`、`function.description` 和 `function.parameters` 四个字段。校验用的是**严格全等匹配**，不存在模糊匹配或前缀匹配。如果传入的工具名不在列表中，立即报错退出，并将全部可用工具名打印到标准错误，方便调用方排查。

[来源](src/commands/tool-call.ts#L11-L17)

## 配置加载与环境初始化

校验通过后，从持久化配置中读取 Embedding 模型参数和 Web Fetch 服务配置，然后调用 `initTools` 将运行时配置注入工具执行上下文：

```ts
const webConfig = !config.webFetchDisabled
  ? { baseUrl: config.webFetchBaseUrl || 'https://r.jina.ai', apiKey: config.webFetchApiKey }
  : { disabled: true, baseUrl: '', apiKey: '' };

if (config.embeddingModel && config.embeddingBaseUrl && config.embeddingApiKey) {
  initTools(
    { provider: config.embeddingProvider || '', model: config.embeddingModel,
      baseUrl: config.embeddingBaseUrl, apiKey: config.embeddingApiKey },
    webConfig,
  );
} else {
  initTools(undefined, webConfig);
}
```

这一步骤的意义在于：`semantic_search` 需要 Embedding 配置来调用模型，`fetch_web_markdown` 需要 Web Fetch 服务的地址和 API Key。如果用户在配置中禁用了 Web Fetch（`webFetchDisabled: true`），则在运行时通过 `getFilteredTools()` 过滤掉 `fetch_web_markdown` 工具，生成引擎和 AI 对话命令会据此调整发送给 LLM 的工具列表。

[来源](src/commands/tool-call.ts#L19-L35)

## 参数 JSON 解析

```ts
let args: any = {};
if (argsJson) {
  try {
    args = JSON.parse(argsJson);
  } catch {
    logError('Invalid JSON arguments');
    process.exit(1);
  }
}
```

参数解析非常轻量：如果提供了第二个命令行参数，就尝试 `JSON.parse`；解析失败则直接退出；没有提供则使用空对象 `{}`。这意味着对于无参数工具（如 `dotenv_template`、`list_wiki_pages`），调用方可以省略 `[args]` 参数。

[来源](src/commands/tool-call.ts#L37-L44)

## 工具分派与执行

最终的调用链落到 `executeToolCall(name, args)`，它维护了一个 `toolHandlers` 映射表，将字符串名字映射到对应的异步处理函数上：

```ts
const toolHandlers: Record<string, (args: any) => Promise<ToolResult>> = {
  list_directory:       (args) => listDirectory(args.dir_path, args.max_depth),
  list_files:           (args) => listFiles(args.path, args.extensions),
  read_file:            (args) => readFileTool(args.file_path, args.start_line, args.end_line),
  search_in_files:      (args) => searchInFiles(args.path, args.pattern, args.extensions),
  git_log:              (args) => gitLog(args.max_count, args.path),
  git_show:             (args) => gitShow(args.object, args.path),
  git_remote_info:      ()    => gitRemoteInfo(),
  dotenv_template:      ()    => dotenvTemplate(),
  list_wiki_pages:      ()    => listWikiPages(),
  read_wiki:            (args) => readWiki(args.slug),
  search_wiki:          (args) => searchWiki(args.query, args.max_results),
  semantic_search:      (args) => semanticSearch(args.query, args.max_results),
  fetch_web_markdown:   (args) => fetchWebMarkdown(args.url),
};
```

每个 handler 都是泛型 `(args: any) => Promise<ToolResult>` 签名，从 args 对象中解构出各自的参数，然后调用底层实现。如果映射表中找不到名字（虽然前面已有校验，但此处作为第二道防线），返回错误结果。这意味着 `executeToolCall` 函数本身可以被其他命令直接复用，而不经过 CLI 参数解析——[AI 对话命令](ai代码问答.md) 和[生成引擎](生成wiki文档.md) 正是这样做的。

## 输出格式：`{type, data}`

所有工具的执行结果统一为 `ToolResult` 类型：

```ts
export interface ToolResult {
  type: 'success' | 'error';
  data: any;
}
```

工具调用命令将其 `JSON.stringify` 后打印到标准输出。不同工具返回的 `data` 结构各不相同：

| 工具 | type 为 success 时的 data 示例 |
|------|-------------------------------|
| `list_directory` | `{name: ".", type: "directory", children: [...]}` |
| `list_files` | `["/abs/path/file1.ts", "/abs/path/file2.ts"]` |
| `read_file` | 文件内容字符串，行范围截取后的文本 |
| `search_in_files` | `[{file: "src/x.ts", line: 10, content: "..."}]` |
| `git_log` | `"abc1234 feat: ...\ndef5678 fix: ..."` |
| `git_remote_info` | `[{name: "origin", url: "...", type: "fetch"}]` |
| `list_wiki_pages` | `["- slug.md \| 标题: ..."]` |
| `read_wiki` | Markdown 文档内容字符串 |
| `search_wiki` / `semantic_search` | `[{slug, title, snippet/score}]` |
| `fetch_web_markdown` | Markdown 格式的网页内容字符串 |

调用方只需检查 `type` 字段——若为 `'error'`，`data` 是错误消息字符串；若为 `'success'`，`data` 的结构取决于具体工具。

[来源](src/ai/tools.ts#L6-L11)

## 13 个工具的完整清单

| 工具名 | 参数 | 用途域 |
|--------|------|--------|
| `list_directory` | `dir_path`, `max_depth?` | 文件系统 |
| `list_files` | `path`, `extensions?` | 文件系统 |
| `read_file` | `file_path`, `start_line?`, `end_line?` | 文件系统 |
| `search_in_files` | `path`, `pattern`, `extensions?` | 文件系统 |
| `git_log` | `max_count?`, `path?` | Git |
| `git_show` | `object`, `path?` | Git |
| `git_remote_info` | 无参数 | Git |
| `dotenv_template` | 无参数 | 环境 |
| `list_wiki_pages` | 无参数 | Wiki |
| `read_wiki` | `slug` | Wiki |
| `search_wiki` | `query`, `max_results?` | Wiki |
| `semantic_search` | `query`, `max_results?` | Wiki（需 Embedding 配置） |
| `fetch_web_markdown` | `url` | 网络（可禁用） |

所有工具均为**只读操作**，不修改文件系统、Git 仓库或配置。语义搜索依赖 Embedding 模型配置，如果未配置则返回错误。Web Fetch 默认使用 `https://r.jina.ai` 作为转换服务，用户可以通过配置切换。

## 在 AI Agent 中的集成场景

`tool-call` 命令的设计初衷是为 [opencode](ai-agent-skill集成.md) 等 AI Agent 提供标准化工具接口。典型的集成流程是：

1. Agent 通过 `toolDefinitions` JSON 了解可用工具及其参数 Schema。
2. Agent 决定调用哪个工具，构造 CLI 命令 `wiki-cli tool-call list_files '{"path":".","extensions":[".ts"]}'`。
3. Agent 从标准输出读取 JSON，检查 `type` 字段。
4. 若为 `'success'`，将 `data` 注入上下文继续推理；若为 `'error'`，可重试或切换策略。

由于工具定义遵循 OpenAI Function Calling Schema，Agent 可以将其直接映射为 LLM 的 `tools` 参数。`getFilteredTools()` 函数会根据运行时配置动态移除被禁用的工具（如 `fetch_web_markdown`），确保 Agent 不会尝试调用不可用的功能。

[来源](src/ai/tools.ts#L269-L276)
