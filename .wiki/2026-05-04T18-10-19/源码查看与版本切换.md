# 源码查看与版本切换

## 架构定位

`/api/source/` 路由将 Wiki 中引用的每一个代码源文件渲染为**独立 HTML 页面**，包含行号、语法高亮、行锚点高亮和历史版本切换。它是 [浏览 Wiki](浏览wiki.md) 中「来源」引用的最终渲染目标。

请求路径的解析链如下：

```
/api/source/src/commands/browse.ts?version=2024-01-01T12-00-00
  ↓ decodeURIComponent → pathname.slice(12) → "src/commands/browse.ts"
  ↓ sanitizePath → 路径穿越校验
  ↓ join(projectRoot, safePath) → 绝对路径
  ↓ readFile → 读取源码
  ↓ extToLang → 语言映射
  ↓ hljs.highlight 逐行渲染 → 行号 HTML
  ↓ 嵌入模板页面 → 返回浏览器
```

整个处理流程集中在 `createServer` 路由回调的条件分支 `pathname.startsWith('/api/source/')` 中。[来源](src/commands/browse.ts#L107-L199)

## 路径穿越防御：`sanitizePath`

```typescript
function sanitizePath(rawPath: string, root: string): string | null {
  const cleaned = rawPath.replace(/^[/\\\\]+/, '');       // 去掉前导 /
  const normalized = normalize(cleaned)
    .replace(/^(\\.\\.(\\/|\\\\))+/g, '');                 // 去掉前导 ../
  const resolved = resolve(root, normalized);
  if (!resolved.startsWith(root + sep) && resolved !== root)
    return null;
  return normalized;
}
```

[来源](src/commands/browse.ts#L244-L252)

三层防御：

| 层级 | 操作 | 目的 |
|------|------|------|
| 1 | 去除首部 `/` 和 `\` | 防止绝对路径注入（如 `/etc/passwd`） |
| 2 | `normalize` + 正则清除 `../` 前缀 | 消灭路径遍历序列（如 `../../etc`） |
| 3 | `resolve(root, normalized)` 后校验前缀 | 确认最终解析路径始终落在 `projectRoot` 子树内 |

注意第三层的边界条件：`root` 自身（`projectRoot`）也被允许，因为顶层 `.wiki` 目录本身就是 `projectRoot` 的子目录。`resolve` 会消耗掉末尾的 `..` 片段，因此需要 `resolved !== root` 作为额外的允许条件。

关键设计决策：`sanitizePath` 接受失败时返回 `null`，调用方输出 403 而非 404。这避免了向潜在攻击者泄露路径是否存在的信息。[来源](src/commands/browse.ts#L111-L116)

## 扩展名到语言映射：`extToLang`

```typescript
function extToLang(ext: string): string {
  const map: Record<string, string> = {
    '.ts': 'typescript',  '.js': 'javascript', '.json': 'json',
    '.md': 'markdown',    '.yml': 'yaml',       '.yaml': 'yaml',
    '.html': 'html',      '.css': 'css',
    '.sh': 'bash',        '.bash': 'bash',
  };
  return map[ext] || 'plaintext';
}
```

[来源](src/commands/browse.ts#L254-L262)

这是一个**退化映射**：只覆盖了该 CLI 项目自身使用的文件类型。未知扩展名降级到 `'plaintext'`，hljs 仍会做基本的 HTML 转义和无色高亮。映射结果同时用于：

1. **传递给 `hljs.highlight`** 作为语言参数，提升高亮准确度
2. **显示在源码页面右上角的标签**中，方便读者确认语言识别结果

## 逐行高亮渲染

传统的 `hljs.highlightAuto` 对整个文件做一次性语法分析，但 `/api/source/` 的实现采用了**逐行调用 `hljs.highlight`** 的策略：

```typescript
const lineHtml = rawLines.map((raw, i) => {
  const num = i + 1;
  let codeHtml: string;
  if (raw.length > 0) {
    const result = hljs.highlight(raw, { language: langName, ignoreIllegals: true });
    codeHtml = result.value;
  } else {
    codeHtml = '&nbsp;';   // 空行保留占位
  }
  return `<div class="line" data-line="${num}">
    <span class="line-num">${num}</span>
    <span class="line-code">${codeHtml}</span>
  </div>`;
}).join('\n');
```

[来源](src/commands/browse.ts#L127-L139)

这种设计的取舍：

- **优势**：每行独立 DOM 节点（`div.line`），CSS 选择器可精确锁定任意行，简化客户端行锚点高亮
- **代价**：单行独立高亮会丢失跨行语法上下文（如多行字符串、多行注释），高亮可能不完整
- **补偿**：`ignoreIllegals: true` 防止单行片段触发报错，牺牲准确度换取渲染稳定性

Git 提交历史证实了逐步演进路径：`9f0f8c3` 添加行号和范围高亮 → `2768e83` 修复为逐行高亮并调整内边距 → `162c547` 收紧行高并修复 hash 选择器。[来源](src/commands/browse.ts#L127-L139)

## 行号锚点高亮：`#L12-L34`

源码页面支持 URL hash 锚点格式 `#L<start>[-L<end>]`，对应 GitHub 风格的源码链接约定。

客户端 JavaScript 在 `DOMContentLoaded` 后解析 hash：

```javascript
var h = location.hash.slice(1);
if (!h) return;
var m = h.match(/^L(\\d+)(?:-L(\\d+))?$/);
if (!m) return;
var s = parseInt(m[1], 10), e = m[2] ? parseInt(m[2], 10) : s;
var target;
for (var i = Math.max(1, s); i <= e; i++) {
  var el = document.querySelector('[data-line="' + i + '"]');
  if (el) { el.classList.add('hl'); if (!target) target = el; }
}
if (target) target.scrollIntoView({ block: 'center' });
```

[来源](src/commands/browse.ts#L161-L172)

关键行为：

- **单行** `#L12` → 等价于 `#L12-L12`，只高亮第 12 行
- **范围** `#L12-L34` → 逐行查找 `[data-line="N"]`，向匹配元素添加 `.hl` 类（蓝色背景+左边框）
- **滚动**：将范围中**第一个**高亮行滚动到视区居中位置（`block: 'center'`），方便用户看到上下文
- **边界保护**：`Math.max(1, s)` 防止负数行号

高亮行的 CSS 样式通过 `border-left: 2px solid #58a6ff` 和淡蓝背景区分。[来源](src/commands/browse.ts#L149-L155)

## 版本切换机制

版本切换的核心需求是让用户回溯到 Wiki 的历史生成结果。系统通过**时间戳目录名**组织版本。

### allVersions：目录扫描与排序

```typescript
const entries = await readdir(wikiDir, { withFileTypes: true });
const allVersions = entries
  .filter(e => e.isDirectory() && e.name !== 'temp' && e.name !== 'sessions')
  .map(e => e.name)
  .sort()
  .reverse();
```

[来源](src/commands/browse.ts#L39-L44)

扫描 `.wiki/` 下的所有子目录，排除 `temp`（临时目录）和 `sessions`（AI 会话目录）[参见 AI 会话管理系统](ai会话管理系统.md)。`sort().reverse()` 的结果是**降序排列**，最新生成的版本在列表首位。

Git 提交 `7408ed0` 明确为过滤 `sessions` 目录所做的修复。[来源](src/commands/browse.ts#L40)

### version 查询参数传递

版本标识以时间戳字符串形式通过 URL 查询参数 `?version=` 在页面间传递：

1. **服务端入口**：根路由 `getVersionFromUrl` 从 `req.url` 中解析 `version` 参数，缺省时取 `latest`（`allVersions[0]`）[来源](src/commands/browse.ts#L57-L64)
2. **API 请求**：`/api/page/*` 和 `/api/source/*` 路由均需要客户端在请求时携带 `version` 参数
3. **页面切换**：当用户通过侧边栏点击切换页面时，`loadPage()` 函数将 `currentVersion` 附加到 API 请求 URL 的 `?version=` 参数上[来源](src/commands/browse.ts#L308-L310)
4. **版本切换**：`switchVersion(ts)` 直接 `window.location.href = '/?version=' + ts` 触发整页重载

### versionOverlay：版本选择浮层

版本选择器通过覆盖层（overlay）实现，HTML 结构如下：

```html
<div class="overlay" id="versionOverlay" onclick="if(event.target===this)hideVersions()">
  <div class="overlay-box">
    <span class="close-btn" onclick="hideVersions()">✕</span>
    <h3>历史版本</h3>
    ${versionsHtml}
  </div>
</div>
```

[来源](src/commands/browse.ts#L291-L296)

覆盖层切换由两个函数驱动：

- `showVersions()`：添加 `show` 类使 `display: none → flex`，显示浮层
- `hideVersions()`：移除 `show` 类，隐藏浮层
- `keydown` 监听 `Escape` 键同样触发隐藏

版本列表由 `buildVersionsHtml` 生成，每个版本项是一个带有 `onclick="switchVersion('...')"` 的 `<a>` 元素，当前版本用 `.current` 类高亮。[来源](src/commands/browse.ts#L229-L232)

### 版本顺序

Git 日志确认项目内部没有对版本目录名做额外排序逻辑，完全依赖目录名的**字典序**。由于时间戳格式 `YYYY-MM-DDTHH-MM-SS` 保证字典序与时间序一致，`sort().reverse()` 能得到正确的从新到旧排列。

## 跨页面源码链接

源码查看页面与 [浏览 Wiki](浏览wiki.md) 页面通过 `fixContentReferences` 函数连接：

```typescript
function fixContentReferences(html: string): string {
  return html.replace(
    /\[来源：([^\]]+)\]/g,
    '<a href="/api/source/$1" target="_blank" class="source-ref">[来源]</a>'
  );
}
```

[来源](src/commands/browse.ts#L264-L266)

它将在 Markdown 渲染结果中出现的 `[来源：src/commands/browse.ts#L107-L199]` 格式文本转换为可点击的源码链接，`target="_blank"` 在新标签页打开。路径中的锚点部分（`#L107-L199`）将直接被浏览器 hash 解析。

## 设计权衡总结

| 维度 | 选择 | 取舍 |
|------|------|------|
| 语法高亮 | 逐行 `hljs.highlight` | 丢失跨行上下文，但支持精确行锚点 |
| 路径安全 | 三层校验 + 403 | 增加复杂度，但防止任意文件读取 |
| 版本组织 | 时间戳目录名 + 字典序 | 依赖目录名格式，但无需元数据文件 |
| 版本切换 | 服务端渲染 + 整页重载 | 实现简单，但丢失滚动位置 |
