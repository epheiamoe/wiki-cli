# 远程仓库支持

wiki-cli 的核心价值在于对 **任意 Git 仓库** 的即用能力。无论是本地已存在的代码库，还是远在 GitHub/GitLab 的私有仓库，只需一条命令即可完成克隆、分析、生成和浏览全流程。

## 双来源输入：`--url` vs `-C`

所有涉及代码分析的命令（`generate`、`ai`、`browse`、`status`）都接受两种来源：

| 来源 | 参数 | 行为 |
|------|------|------|
| 本地目录 | `-C, --dir <path>` | 直接使用指定目录，默认当前工作目录 |
| 远程仓库 | `-u, --url <url>` | 克隆或更新仓库到本地缓存，再执行操作 |

`--url` 的核心处理在 `resolveWorkDir` 函数中，它接管了后续所有流程的工作目录。

[来源](src/cli.ts#L55-L66) · [来源](src/utils/workspace.ts#L24-L27)

## 仓库缓存：~/.wiki-cli/repos/

当指定 `--url` 且 **未使用 `--temp`** 时，仓库被克隆到持久化缓存目录：

```
~/.wiki-cli/repos/<url-derived-name>/
```

目录名的生成规则由 `urlToDirName` 负责：移除 `https://` 前缀和 `.git` 后缀，将 `:/` 替换为 `-`。

```
git@github.com:user/repo.git  →  git@github.com-user-repo
https://github.com/user/repo  →  github.com-user-repo
```

[来源](src/utils/workspace.ts#L13-L20)

### 缓存复用与增量更新

当目标目录已存在时，`ensureRepo` 不会重新克隆，而是执行增量更新：

1. `git fetch --all` 获取远程最新提交
2. 如果指定了 `--branch`：先 `git checkout <branch>`，再 `git merge origin/<branch>`
3. 未指定分支：执行 `git merge`（合并当前分支的远程跟踪分支）

**网络容错**：如果 `git fetch` 因网络不可用而失败，函数返回 `{ updated: false }`，调用侧（`generateCommand`）会检测并询问用户是否使用已有缓存继续。这在离线环境下依然可用。

[来源](src/utils/git.ts#L10-L38) · [来源](src/commands/generate.ts#L60-L84)

## 临时模式：`--temp`

`--temp` 改变目标目录的决策逻辑：

```
不指定 --temp → ~/.wiki-cli/repos/<name>/  (持久化缓存)
指定 --temp   → 系统临时目录 wiki-cli-XXXXX/  (用完即焚)
```

临时模式的核心差异在 `resolveWorkDir` 中体现：

```typescript
if (temp) {
  targetDir = mkdtempSync(join(tmpdir(), 'wiki-cli-'));
} else if (output) {
  targetDir = resolve(output);
} else {
  targetDir = defaultRepoUrl(url);
}
```

临时目录的清理由 `cleanup` 函数完成，它在生成结束后被调用：

```typescript
if (temp) {
  return {
    workDir: targetDir,
    updated: repoResult.updated,
    cleanup: async () => {
      const { rm } = await import('node:fs/promises');
      await rm(targetDir, { recursive: true, force: true });
    },
  };
}
```

典型场景：CI/CD 流水线中临时克隆、生成、浏览，完成后不留痕迹。

[来源](src/utils/workspace.ts#L31-L60)

## 分支管理：`--branch`

`--branch` 参数在远程和本地两种来源中的行为一致：

- **远程来源（`--url`）**：传递给 `git clone --branch <name>`，缓存更新时执行 `git checkout <name>` + `git merge origin/<name>`
- **本地来源（`-C`）**：直接在本地仓库执行 `git checkout <branch>`

如果指定的分支不存在（本地或远程），命令会以错误退出。

[来源](src/utils/workspace.ts#L66-L75) · [来源](src/utils/git.ts#L15-L16)

## 浅克隆：`--depth`

`--depth <n>` 控制 `git clone` 的深度，对应 `--depth` 参数。深层历史不必要（AI 分析只看代码文件），浅克隆能显著加速大仓库的首次拉取。该参数仅在首次克隆时生效，后续增量更新会拉取完整引用。

[来源](src/utils/git.ts#L13-L14)

## 输出目录与 `--output` 的协同

`--url` + `--output <path>` 的组合将克隆目标定向到指定路径，同时该路径也成为 Wiki 的输出目录。这在需要精确控制文件布局的场景下很有用。

[来源](src/utils/workspace.ts#L35-L37)

## 跨命令复用

`browse --url` 和 `status --url` 不执行克隆，只通过 `defaultRepoDir(url)` 查找缓存仓库中的 `.wiki` 目录：

```typescript
// browse.ts
const repoDir = defaultRepoDir(options.url);
wikiDir = join(repoDir, '.wiki');

// status.ts
const repoDir = defaultRepoDir(options.url);
wikiDir = join(repoDir, '.wiki');
```

这意味着：先用 `wiki-cli generate --url ...` 生成 Wiki，之后用 `wiki-cli browse --url ...` 或 `wiki-cli status --url ...` 时无需再次指定路径。

[来源](src/commands/browse.ts#L27-L29) · [来源](src/commands/status.ts#L23-L25)

## 完整示例

一条命令完成从远程仓库到浏览的全流程：

```bash
wiki-cli generate \
  --url git@github.com:user/repo.git \
  --branch main \
  --parallel \
  --browse
```

执行顺序：
1. 将 `user/repo` 克隆到 `~/.wiki-cli/repos/git@github.com-user-repo/`
2. 检出 `main` 分支
3. 两阶段生成 Wiki（断点续传与并发生成和并行加速）
4. 自动启动 HTTP 服务器并打开浏览器（内置 HTTP 服务器）
