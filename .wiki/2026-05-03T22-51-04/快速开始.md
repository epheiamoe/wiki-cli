# 快速开始：5 分钟上手 Wiki CLI

打开终端，跟随以下四个步骤，从零开始为你的代码仓库自动生成结构化 Wiki 文档。

---

## 第一步：安装

确保当前系统已安装 **Node.js >= 18**，然后执行：

```bash
npm install -g wiki-cli
```

安装完成后验证：

```bash
wiki-cli --version
```

预期输出：

```
1.0.0
```

> **不想全局安装？** 你也可以用 `npx` 直接运行：`npx wiki-cli config`、`npx wiki-cli generate`……所有命令完全一致，无需安装步骤。

[来源](package.json#L3-L8)

## 第二步：配置 LLM

Wiki CLI 依赖 LLM（大语言模型）来分析和生成文档。首次使用**必须**配置 API Key。

```bash
wiki-cli config
```

此时会启动交互式引导，依次询问你：

1. **选择 LLM 提供商** — 内置支持 OpenAI、DeepSeek、Google Gemini、Anthropic、xAI Grok、Kimi (Moonshot)、Mistral 七大厂商，你也可以选择「Custom」手动输入
2. **选择模型** — 每个提供商下列出可用模型及定价提示
3. **输入 API Key** — 以 `*` 掩码输入，安全存储
4. **确认 JSON 模式支持** — 已知提供商会自动判断，未知的会询问你
5. **选择文档语言** — 输入 `zh`（中文）或 `en`（英文）

以选择 **DeepSeek** 为例，交互过程大致如下：

```
? Select LLM provider: (Use arrow keys)
❯ OpenAI
  Google Gemini
  Anthropic
  xAI Grok
  DeepSeek
  Kimi (Moonshot)
  Mistral
  ✏️  Custom (enter manually)

? Select model for DeepSeek: (Use arrow keys)
❯ deepseek-v4-pro - DeepSeek v4 Pro (Balanced)
  deepseek-v4-flash - DeepSeek v4 Flash (Fast & cheap)

? Enter API Key: [输入你的 sk- 开头密钥]
? Documentation language (zh/en, default zh): zh

✅ Configuration saved to C:\Users\你的用户名\.wiki-cli\config.json
```

### 非交互模式（一键配置）

你也可以跳过交互流程，直接在命令行中传参：

```bash
wiki-cli config --provider DeepSeek --model deepseek-v4-flash --api-key sk-你的密钥 --lang zh
```

### 配置存储位置

配置保存在 **用户目录** 下的 `.wiki-cli/config.json`：

```json
{
  "provider": "DeepSeek",
  "baseUrl": "https://api.deepseek.com",
  "model": "deepseek-v4-flash",
  "apiKey": "sk-你的密钥",
  "lang": "zh"
}
```

如需修改，可以重新运行 `wiki-cli config` 或用文本编辑器直接编辑此文件。

## 第三步：生成 Wiki

进入你的项目根目录，执行：

```bash
wiki-cli generate
```

工具会自动完成两大阶段：

### 阶段一：仓库分析 & 大纲生成

工具会使用 LLM 读取你的项目结构，分析文件依赖与功能模块，自主调用文件读取工具探索仓库，最终输出一个 JSON 格式的文档大纲。

```
ℹ Phase 1: Analyzing repository and generating outline...
ℹ LLM round 1 (streaming below)...
Thinking: 分析项目结构...
ℹ Executing 2 tool call(s)...
  🔧 list_directory({ "path": ".", "maxDepth": 3 })
  ✅ Result: ...
ℹ LLM round 2 (streaming below)...
...
✅ Generated 12 topics.
```

### 阶段二：逐个生成 Wiki 页面

大纲生成后，工具会依次为每个主题生成独立页面。你可以在串行模式和并行模式间选择：

- **串行模式**（默认）— 逐页生成，可实时看到流式输出
- **并行模式** — 多页同时生成，速度更快，但不显示中间流式内容

```
? Generate pages in parallel? (faster, no streaming output) (y/N) y
? Number of concurrent page generations: 3

ℹ Phase 2: Generating Wiki pages...
✅ [1/12] Generated: 概览
✅ [2/12] Generated: 快速开始
✅ [3/12] Generated: 配置命令
...
✅ [12/12] Generated: 测试策略

✅ Wiki generated at .wiki/20250101_120000
✅ Index file generated.
```

### 断点续传

如果生成过程中意外中断，只需再次运行 `wiki-cli generate`，工具会自动检测到之前的检查点，询问你是否继续：

```
? Previous generation temp data found. What do you want to do?
❯ 🔄 Resume from last checkpoint
  🗑️  Discard and start fresh
```

选择「Resume」即可从断点继续，已完成的页面不会重复生成。

## 第四步：浏览 Wiki

生成完成后，启动本地服务器查看文档：

```bash
wiki-cli browse
```

预期输出：

```
ℹ Browsing Wiki: 20250101_120000
✅ Wiki server started at http://localhost:3000
```

浏览器会自动打开。你会看到一个深色主题的文档站点：

- **左侧**：侧边栏目录，按章节分组，带难度标识（🟢 初学 / 🟡 中级 / 🔴 高级）
- **右侧**：Markdown 渲染内容，带代码语法高亮
- **右上角**：「历史版本」按钮，可切换不同时间生成的版本

每次生成都会在 `.wiki/` 下创建一个新的时间戳子目录，`browse` 服务默认加载最新版本。

## 项目产物结构

生成完成后，项目根目录下会出现 `.wiki/` 文件夹，结构如下：

```
.your-project/
├── .wiki/
│   ├── 20250101_120000/         # 第一次生成的版本（按时间戳命名）
│   │   ├── index.json           # 目录索引（供浏览器侧边栏使用）
│   │   ├── 概览.md              # 每个页面是一个独立的 Markdown 文件
│   │   ├── 快速开始.md
│   │   ├── 配置命令-wiki-cli-config.md
│   │   ├── 浏览命令-wiki-cli-browse.md
│   │   └── ...
│   ├── 20250102_090000/         # 第二次生成的版本
│   │   └── ...
│   └── temp/                    # 临时检查点目录（生成中断时用于恢复）
└── src/                         # 你的项目代码
```

每次运行 `wiki-cli generate` 都会生成一个独立版本，互不覆盖，历史版本可在浏览器中通过「历史版本」按钮切换查看。
