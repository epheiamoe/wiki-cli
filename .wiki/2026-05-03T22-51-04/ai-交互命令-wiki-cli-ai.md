# AI 交互命令：`wiki-cli ai`

`wiki-cli ai` 是一条基于 LLM 的代码库智能问答命令。它让你用自然语言与当前项目的代码仓库对话——查询架构、理解实现、定位逻辑——而不必手动翻阅文件。其核心设计围绕两种问答模式、一套完整的会话生命周期，以及一个"Wiki 优先"的上下文获取策略展开。

## 两种问答模式

命令支持两种截然不同的使用方式，适用于不同的场景节奏。

### 单次问答模式（`--question` / `--answer-only`）

通过 `--question` 参数直接传入问题，命令执行一次问答后自动退出。适合脚本调用、快速查询或 CI 集成场景。

```bash
wiki-cli ai --question "这个项目的入口文件在哪？"
```

如果加上 `--answer-only`，输出将仅包含纯文本答案，不显示推理过程、工具调用日志或任何装饰性输出——便于将结果通过管道传递给其他工具。

```bash
wiki-cli ai --question "项目的依赖管理使用什么工具？" --answer-only
```

两者的内部路径不同：`--answer-only` 走 `answerOnly()` 函数，使用非流式请求一次性获取完整响应；普通 `--question` 走 `chatOnce()`，使用流式输出逐字渲染。两种路径都支持工具调用的多轮循环（最多 50 轮），**工具调用的结果在终端不可见**——仅在 `--answer-only` 模式下抑制所有日志。两种模式在问答结束后都会将会话保存到磁盘。 [来源](src/commands/ai.ts#L103-L139)

### 交互式模式

未提供 `--question` 时，命令进入交互式循环。终端显示 `You > ` 提示符，持续接受用户输入直到输入 `/exit` 或 `/quit`。每轮对话都会自动保存，确保进程意外中断时不会丢失上下文。 [来源](src/commands/ai.ts#L241-L243)

| 特性 | 单次问答 | 交互式 |
|------|---------|--------|
| 使用方式 | `--question "..."` | 无参数启动 |
| 输出风格 | 流式或纯文本 | 流式 |
| 会话保存 | 自动保存后退出 | 每轮自动保存 |
| 斜杠命令 | 不支持 | 全部支持 |
| 适用场景 | 快速查询、CI | 深度探索、多轮对话 |

## 会话生命周期

会话（Session）是对话上下文的持久化载体，其生命周期贯穿三个步骤。

```
┌──────────────────────────────────────────────┐
│              启动命令                          │
│  ┌─────────────────────────────────────┐     │
│  │ createSession() → 生成 8 位 ID       │     │
│  │ 写入 .wiki/sessions/{id}.json       │     │
│  └─────────────────────────────────────┘     │
│                      ▼                       │
│  ┌─────────────────────────────────────┐     │
│  │ interactiveLoop() 或 chatOnce()      │     │
│  │ 对话 + 工具调用循环（最多 50 轮）    │     │
│  └─────────────────────────────────────┘     │
│                      ▼                       │
│  ┌─────────────────────────────────────┐     │
│  │ saveSession() → 更新 updated 时间戳  │     │
│  │ 覆写 .wiki/sessions/{id}.json       │     │
│  └─────────────────────────────────────┘     │
└──────────────────────────────────────────────┘
```

**`createSession()`**：在 `.wiki/sessions/` 目录下创建一个新 JSON 文件。会话 ID 取 UUID 前 8 位，初始 `summary` 为"新会话"。如果指定了 `--session` 参数，则加载已有会话替代创建。

**`interactiveLoop()`**：这是交互模式的主循环。每轮从终端读取输入，识别斜杠命令或调用 `chatOnce()` 处理对话。`chatOnce()` 内部实现了流式输出 + 工具调用的多轮循环——每次 LLM 返回工具调用时，自动执行工具并将结果追加回消息列表，循环最多 50 次以防止无限递归。

**`saveSession()`**：更新 `updated` 时间戳为当前时间，将 `messages`（不含 system prompt）和 `summary` 写入文件。交互模式下每轮对话后自动调用，单次问答模式下退出前调用一次。 [来源](src/commands/ai.ts#L145-L148) [来源](src/ai/ai-session.ts#L67-L71)

## 斜杠命令

交互模式下所有以 `/` 开头的输入被识别为命令，由 `interactiveLoop()` 内部的命令调度器处理。

```bash
/help             # 显示所有斜杠命令列表
/exit 或 /quit    # 保存当前会话后退出
/save             # 手动保存会话
/clear            # 清屏
/session          # 显示当前会话 ID 和摘要
/sessions         # 列出所有保存的会话（含时间戳和摘要）
/switch <id>      # 保存当前会话，切换到指定 ID 的会话
/new              # 保存当前会话，创建新会话
/wiki             # 调用 generate 命令生成 Wiki 文档
```

`/switch` 和 `/new` 的执行流程都遵循"先保存旧会话，再加载/创建新会话"的模式，保证不会丢失任何对话历史。`/wiki` 命令通过动态 `import('./generate.js')` 调用生成管线，不中断当前会话状态。 [来源](src/commands/ai.ts#L164-L233)

## Wiki 工具优先策略

这是 `wiki-cli ai` 最核心的设计决策：**在回答代码问题前，优先查询已有的 Wiki 文档**。

```
┌── 启动时检测 ──────────────────────────────────┐
│  检查 .wiki/ 目录是否存在且包含版本子目录        │
│  （排除 temp 和 sessions 目录）                 │
└─────────────────────────────────────────────────┘
          │
          ├── 有 Wiki ────────────────────────────┐
          │   注册全部 10 个工具，包括：           │
          │   • list_wiki_pages                   │
          │   • read_wiki                         │
          │   • 8 个源码/Git 探索工具             │
          │   系统提示词中嵌入 Wiki 信息段落       │
          │                                      │
          └── 无 Wiki ────────────────────────────┐
              提示用户 "要先生成吗？ (Y/n)"        │
              ├── 接受 → 调用 generate 命令       │
              └── 拒绝 → 仅注册 8 个非 Wiki 工具  │
                        系统提示词注明"没有 Wiki"  │
```

这一策略在三个层面落地：

1. **工具注册层面**：有 Wiki 时，LLM 可选 `list_wiki_pages` 和 `read_wiki` 两个工具；无 Wiki 时这两个工具从 `toolDefinitions` 中被过滤掉，LLM 不会尝试调用它们。 [来源](src/commands/ai.ts#L66-L69)

2. **提示词层面**：系统提示词模板 `prompts/ai-system.md` 中嵌入了 Wiki 信息区块，明确指示 LLM "始终优先使用 Wiki 工具快速获取上下文"。同时包含一条安全条款：**"Wiki 可能落后于代码，最终答案必须基于实际代码验证"**。 [来源](prompts/ai-system.md#L7-L9)

3. **体验层面**：如果项目完全没有 Wiki，命令不会直接拒绝，而是询问用户是否要立即生成。这一交互发生在启动阶段、进入问答之前。 [来源](src/commands/ai.ts#L51-L63)

这种设计让 LLM 既能快速从预先生成的 Wiki 中获取项目全貌（避免盲目读取大量源文件），又能结合源码工具做精确验证——兼顾效率与准确性。关于工具系统的完整定义，参见[工具系统与函数调用](工具系统与函数调用.md)；关于会话管理的存储细节，参见 [AI 会话管理](ai-会话管理.md)。
