# 配置存储与高级选项

## 配置文件的存储位置

Wiki CLI 使用 `~/.wiki-cli/config.json` 作为全局配置文件。路径由 `homedir()` 拼接 `.wiki-cli` 目录构成，跨平台适配——Windows 上解析为 `C:\Users\<用户名>\.wiki-cli\config.json`，macOS/Linux 上解析为 `/home/<用户名>/.wiki-cli/config.json`。

[来源](src/config/config-store.ts#L23-L24)

配置目录和路径分别由 `getConfigDir()` 和 `getConfigPath()` 两个导出函数提供，便于其他模块获取：

```typescript
const CONFIG_DIR = join(homedir(), '.wiki-cli');
const CONFIG_PATH = join(CONFIG_DIR, 'config.json');
```

[来源](src/config/config-store.ts#L23-L24)

## WikiCliConfig 接口字段详解

配置文件的 JSON 结构对应 `WikiCliConfig` 接口：

```typescript
export interface WikiCliConfig {
  provider: string;
  baseUrl: string;
  model: string;
  apiKey: string;
  lang: string;
  jsonMode?: boolean;
}
```

[来源](src/config/config-store.ts#L5-L13)

各字段含义：

| 字段 | 类型 | 可选性 | 说明 |
|------|------|--------|------|
| `provider` | `string` | **必填** | 提供商名称，如 `"OpenAI"`、`"Custom"`。内置提供商列表见 [](llm-提供商与模型选择.md)。 |
| `baseUrl` | `string` | **必填** | API 端点地址。内置提供商有预设值，Custom 模式下需用户手动输入。 |
| `model` | `string` | **必填** | 模型标识符，如 `"gpt-5.5"`。Custom 模式下可自由输入任何模型名。 |
| `apiKey` | `string` | **必填** | API 密钥，以明文存储在配置文件中。 |
| `lang` | `string` | **必填** | 文档生成语言，默认 `"zh"`，可选 `"en"`。 |
| `jsonMode` | `boolean` | **可选** | JSON 输出模式开关。不设置时默认为 `undefined`，生成命令视其为 `false`。 |

**重要安全说明**：`apiKey` 以明文存储在配置文件中。如果与其他人共享系统，建议设置配置文件权限为仅当前用户可读写。

## JSON 模式：`jsonMode` 的作用

`jsonMode` 是控制 LLM 是否使用 `response_format: json_object` 响应的开关。开启后，LLM 保证输出合法 JSON，大幅提高大纲解析成功率。

判断流程分为三种情况：

```
提供商是否已知支持 JSON 模式？
  ├── 是 → jsonMode = true（自动启用）
  ├── 否 → jsonMode = false（自动禁用）
  └── Custom（未知）→ 交互式询问用户
```

[来源](src/commands/config.ts#L78-L91)

具体来说，`[配置命令：wiki-cli config](配置命令-wiki-cli-config.md)` 的交互流程中：

1. 用户选择提供商后，调用 `supportsJsonMode(provider)` 获取结果。
2. 如果结果是 `true` 或 `false`，直接赋值给 `jsonMode`，跳过用户询问。
3. 如果结果是 `undefined`（仅 Custom 提供商），则弹出确认提示："Does this provider support JSON output mode (response_format: json_object)?"，默认值为 `true`，由用户决定。

[来源](src/commands/config.ts#L78-L91)

在生成阶段，`[生成命令：wiki-cli generate](生成命令-wiki-cli-generate.md)` 读取配置：

```typescript
const useJsonMode = config.jsonMode === true;
```

[来源](src/commands/generate.ts#L139)

只有当 `jsonMode` 严格等于 `true` 时才启用 JSON 模式。`undefined` 和 `false` 的行为一致——不启用。JSON 模式会传入 `LLMClient` 的 `chat()` 和 `chatStream()` 方法，在 API 请求体中附加 `response_format: { type: "json_object" }`。

[来源](src/ai/llm-client.ts#L64)

## `supportsJsonMode` 函数：已知与未知提供商

```typescript
const JSON_MODE_PROVIDERS = new Set([
  'OpenAI',
  'DeepSeek',
  'xAI Grok',
  'Mistral',
  'Kimi (Moonshot)',
]);

export function supportsJsonMode(provider: string): boolean | undefined {
  if (provider === 'Custom') return undefined; // unknown, ask user
  return JSON_MODE_PROVIDERS.has(provider);
}
```

[来源](src/config/config-store.ts#L26-L35)

判断逻辑：

- **已知支持的提供商**：OpenAI、DeepSeek、xAI Grok、Mistral、Kimi (Moonshot) → 返回 `true`。
- **已知不支持的提供商**：Google Gemini、Anthropic → 返回 `false`。这些提供商的 API 不支持 `response_format: json_object`，强制开启会导致 API 错误。
- **Custom（未知）**：返回 `undefined`，由用户在交互式配置中自行决定。

**注意**：Google Gemini 和 Anthropic 不在 JSON_MODE_PROVIDERS 集合中，因此 `supportsJsonMode` 对它们返回 `false`。如果你使用 Custom 模式连接兼容 OpenAI API 的第三方服务（如 Ollama、vLLM），应自行确认是否支持 JSON 模式并手动开启。

## 端口冲突处理：`findFreePort` 策略

`[浏览命令：wiki-cli browse](浏览命令-wiki-cli-browse.md)` 启动 HTTP 服务时，默认首选端口为 **3000**。如果该端口已被占用，`findFreePort` 采用**线性递增探测**策略：

```typescript
async function findFreePort(preferred: number): Promise<number> {
  return new Promise((resolve) => {
    const srv = createServer();
    srv.listen(preferred, () => {
      const addr = srv.address();
      if (addr && typeof addr === 'object') {
        srv.close(() => resolve(addr.port));
      } else {
        srv.close(() => resolve(preferred));
      }
    });
    srv.on('error', () => resolve(findFreePort(preferred + 1)));
  });
}
```

[来源](src/commands/browse.ts#L312-L323)

流程说明：

1. 尝试在 3000 端口启动一个临时 HTTP 服务。
2. 如果 `listen` 成功（无错误），记录实际分配的端口号，立即关闭临时服务，返回该端口。
3. 如果 `listen` 触发 `error` 事件（通常是 `EADDRINUSE`），以 `preferred + 1` 递归重试。
4. 递归持续递增，直到找到一个可用端口。在实践中，3000、3001、3002……依次尝试，通常第一或第二个即成功。

**用户不会直接感知此过程**——终端只输出最终使用的端口号。如果你希望固定端口，可以先手动释放 3000 端口的占用进程。

## 完整配置文件示例

以下是一个典型的配置文件内容，标注了各字段的可选性：

```json
{
  "provider": "DeepSeek",       // 必填，字符串
  "baseUrl": "https://api.deepseek.com",  // 必填，字符串
  "model": "deepseek-v4-pro",   // 必填，字符串
  "apiKey": "sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",  // 必填，字符串
  "lang": "zh",                 // 必填，字符串，默认 "zh"
  "jsonMode": true              // 可选，布尔值，不设置则无此字段
}
```

Custom 提供商示例：

```json
{
  "provider": "Custom",
  "baseUrl": "https://your-proxy.example.com/v1",
  "model": "your-custom-model",
  "apiKey": "sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
  "lang": "en",
  "jsonMode": true
}
```

## `.wiki-cli/` 目录的创建时机与权限

`.wiki-cli/` 目录及其内部的 `config.json` 文件在调用 **`saveConfig`** 函数时创建：

```typescript
export async function saveConfig(config: WikiCliConfig): Promise<void> {
  await mkdir(CONFIG_DIR, { recursive: true });
  await writeFile(CONFIG_PATH, JSON.stringify(config, null, 2), 'utf-8');
}
```

[来源](src/config/config-store.ts#L43-L46)

关键行为：

- **创建时机**：仅在首次执行 `[配置命令：wiki-cli config](配置命令-wiki-cli-config.md)` 保存配置时创建。`loadConfig` 不会创建目录，如果配置文件不存在，它只是返回 `null`。
- **递归创建**：`mkdir` 使用 `{ recursive: true }`，即使父级目录不存在也会一并创建，不会因中间目录缺失而报错。
- **写入格式**：JSON 使用 `null, 2` 美化缩进，手动编辑时方便阅读。
- **权限注意事项**：
  - 默认情况下，Node.js 的 `writeFile` 使用系统默认的文件权限（Unix: `0666 & ~umask`，通常为 `644`）。
  - 如果系统中有其他用户，建议手动设置 `config.json` 为 `600`（仅所有者读写），或确保 `~/.wiki-cli/` 目录权限为 `700`。
  - `apiKey` 明文存储——如果配置文件被泄露，API 密钥将完全暴露。
