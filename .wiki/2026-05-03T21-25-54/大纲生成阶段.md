整个 `wiki-cli generate` 分为两个阶段，**大纲生成阶段**（Phase 1）是决定输出质量的关键前置环节——LLM 使用只读工具探索仓库，通过多轮对话迭代生成结构化的 JSON 大纲。本文深入剖析其实现细节。

## 多轮对话迭代：从自由探索到收敛

`generateOutline` 的核心是一个上限 25 轮的迭代循环。每轮开始时，它向 LLM 发送当前累积的 `messages` 数组（初始包含 system + user 两条消息），然后调用 `collectFullResponse` 获取完整响应。[来源](src/commands/generate.ts#L131-L137)

```typescript
for (let i = 0; i < maxIterations; i++) {
  const fullContent = await collectFullResponse(client, messages, config, true, useJsonMode);
  // 尝试解析 JSON...
  // 若失败，将 LLM 回复追加到 messages，继续下一轮
  messages.push({ role: 'assistant', content: fullContent });
}
```

每轮回复之后，系统调用 `parseOutlineJson` 尝试从文本中提取合法 JSON。**解析成功即终止循环**，并将原始文本写入 `_outline.json`；解析失败则将本次回复追加到消息历史中，让 LLM 在下一轮获得上下文继续修正。[来源](src/commands/generate.ts#L149-L162)

这种设计隐含一个关键假设：LLM 可能在早期回复中包含工具调用（探索仓库），只有在充分理解项目结构后才会输出最终 JSON。25 轮上限防止了无限循环，即使全部失败，最后还会对 `finalContent` 做一次兜底解析。[来源](src/commands/generate.ts#L170-L176)

## 内在提示词：引导 LLM 的四步分析法

system prompt（`outline-system.md`）给 LLM 设定了一个结构化的思考框架：

1. **高层愿景与价值**：项目解决什么问题
2. **架构深度剖析**：识别核心模块及交互关系
3. **受众分析**：确定文档面向前端/后端/算法/学习者
4. **生成 JSON 目录**：按指定结构输出

User prompt（`outline-user.md`）则是一条简洁的执行指令："使用工具探索项目，按分析框架生成 JSON 目录，仅输出 JSON，不要加额外文字"。[来源](prompts/outline-user.md#L1-L12)

提示词模板中注入了 `workDir`、`os`、`lang` 三个变量，由 `renderPrompt` 在运行时填充。[来源](src/commands/generate.ts#L109-L112)

## 工具系统：LLM 理解仓库的触手

System prompt 明确列出了 LLM 可调用的 10 个只读工具，这些工具在 `src/ai/tools.ts` 中实现：

| 工具 | 用途 | 关键参数 |
|------|------|----------|
| `list_directory` | 获取目录树 | `dir_path`, `max_depth`(默认3) |
| `list_files` | 列举文件（可过滤扩展名） | `path`, `extensions[]` |
| `read_file` | 读取文件内容（可限行） | `file_path`, `start_line`, `end_line` |
| `search_in_files` | 搜索关键字/正则 | `path`, `pattern`, `extensions[]` |
| `git_log` | 查看提交历史 | `max_count`(默认20), `path` |
| `git_show` | 查看 Git 对象 | `object`, `path` |
| `git_remote_info` | 查看远程仓库 | — |
| `dotenv_template` | 读取 `.env.example` | — |
| `list_wiki_pages` | 列出已生成 Wiki 页面 | — |
| `read_wiki` | 读取已生成 Wiki 页面 | `slug` |

[来源](src/ai/tools.ts#L1-L120)

工具调用在 `collectFullResponse` 内部被完整编排：流式模式下逐 chunk 累积 `tool_call` 参数（处理同名工具调用的增量参数追加），非流式模式一次性获取；全部工具执行完毕后将结果作为 `role: 'tool'` 消息追加到对话，然后进入下一轮工具调用或返回最终文本。最多允许 30 次工具迭代。[来源](src/commands/generate.ts#L239-L329)

## parseOutlineJson：容错解析的四层防线

从 LLM 原始输出到 `Topic[]` 的转换，经历了四条防线：

```
原始文本 → stripCodeFence → 正则提取 JSON → JSON.parse → 结构验证
```

**第一层：`stripCodeFence`**。移除 Markdown 代码块标记（`` ```json `` 和 `` ``` ``），兼容 LLM 在输出外层包裹代码块的行为。[来源](src/ai/llm-client.ts#L52-L54)

**第二层：正则提取**。`text.match(/\{[\s\S]*\}/)` 贪婪匹配第一个 `{` 到最后一个 `}`，提取最外层 JSON 对象。即使 LLM 在 JSON 前后添加了额外文字，这一层也能剥离出有效载荷。[来源](src/commands/generate.ts#L188-L189)

**第三层：`JSON.parse`**。标准解析，失败则静默返回空数组。[来源](src/commands/generate.ts#L191)

**第四层：结构验证**。检查 `parsed.sections` 是否为数组；遍历每个 section，检查 `section.topics` 是否为数组；对每个 topic 区分 `type === 'group'`（分组标题）和常规页面。[来源](src/commands/generate.ts#L192-L217)

## Legacy 兼容：brief → description + task

早期版本的 topic 只包含一个 `brief` 字段。在当前的 schema 中，每个 topic 需要两个字段：
- **`description`**：30-80 字的页面简介，会被所有页面看到（注入到 page prompt 的 `availablePages`）
- **`task`**：50-150 字的生成指令，仅目标页面收到

兼容逻辑如下：

```typescript
const description = item.description || item.brief || '';
const task = item.task || item.brief || '';
```

[来源](src/commands/generate.ts#L208-L209)

如果 LLM 只输出了 `brief`，则 `description` 和 `task` 都回退到 `brief` 的值。这意味着旧的 LLM 模型无需修改即可生成新格式的兼容输出，但质量会打折扣——因为 `description` 和 `task` 的角色完全不同，共用同一文本会导致页面上下文信息不足。

## JSON 模式开关

当配置项 `jsonMode` 为 `true` 时，请求体中会附加 `response_format: { type: 'json_object' }`，强制 LLM 输出合法 JSON。[来源](src/commands/generate.ts#L120) 这能显著减少解析失败的概率，但前提是模型支持该功能（如 `gpt-4-1106-preview` 及后续版本）。注意：开启 JSON 模式后，部分模型的 `reasoning_content` 字段可能不可用。[来源](src/ai/llm-client.ts#L66-L68)

## _outline.json 的临时持久化

大纲生成成功后，原始 LLM 输出被写入 `.wiki/temp/_outline.json`：

```typescript
await writeTextFile(join(TEMP_DIR, '_outline.json'), fullContent);
```

[来源](src/commands/generate.ts#L155)

这个文件有两个作用：
1. **断点恢复**：当生成中断后重新运行，[断点续传与重试机制](断点续传与重试机制.md) 检测到 `.wiki/temp` 目录存在，询问用户是恢复还是重新开始。
2. **索引重建**：Phase 2 结束后，`generateIndex` 函数会从内存中的 `topics` 数组重建 `index.json`，写入最终输出目录。如果 Phase 2 直接使用内存数据而非重新解析 `_outline.json`，意味着一旦 Phase 1 完成，该文件仅在断点场景下有用。
