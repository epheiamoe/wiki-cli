# 提示词模板引擎

提示词模板引擎是连接 LLM 与代码逻辑的桥梁。它将系统提示词从 TypeScript 代码中解耦为独立的 Markdown 文件，通过 Mustache 风格的 `{{var}}` 占位符实现运行时变量注入。整个引擎只有三个函数、五个模板文件，却是整个生成流程的"灵魂"——它决定了 LLM 以什么身份、用什么框架、写什么内容。

## 三函数引擎

引擎位于 `src/ai/prompts.ts`，核心流程是一条清晰的管道：

```
loadPrompt（读文件） → fillPrompt（替换占位符） → renderPrompt（组合）
```

```mermaid
flowchart LR
    A[prompts/*.md] -->|loadPrompt| B[原始模板字符串]
    B -->|fillPrompt| C[渲染后的提示词]
    D[{ 变量字典 }] -->|fillPrompt| B
```

三个函数的职责分工如下：

| 函数 | 签名 | 职责 |
|------|------|------|
| `loadPrompt` | `(filename: string) => Promise<string>` | 读取 `prompts/` 目录下的模板文件，返回原始字符串 |
| `fillPrompt` | `(template: string, vars: PromptVars) => string` | 遍历 `vars` 字典，用 `replace(RegExp)` 全局替换 `{{key}}` 占位符 |
| `renderPrompt` | `(filename: string, vars: PromptVars) => Promise<string>` | 先 `loadPrompt` 再 `fillPrompt`，一步到位 |

[来源](src/ai/prompts.ts#L14-L29)

`PromptVars` 是一个简单的键值对接口：`{ [key: string]: string }`。所有值都必须是字符串，不含类型转换或嵌套结构。[来源](src/ai/prompts.ts#L9-L11)

## 五个模板的用途

`prompts/` 目录下五个 Markdown 文件，对应两个生成阶段加一个交互模式：

### AI 交互模式

**`ai-system.md`** — 用于 [`wiki-cli ai`](ai-交互命令-wiki-cli-ai.md) 命令。定义了 LLM 的角色（"资深代码分析师"）和行为准则：优先使用 Wiki 工具获取上下文，以实际代码为准，回答要简洁结构化。包含三个变量占位符：`{{workDir}}`、`{{os}}`、`{{wikiInfo}}`。[来源](prompts/ai-system.md#L1-L10)

### 大纲生成阶段（Phase 1）

[`大纲生成阶段`](大纲生成阶段.md) 使用两个模板配对：

- **`outline-system.md`** — 系统提示词。定义 LLM 的角色（"资深软件工程师兼技术文档专家"）和分析框架：高层愿景 → 架构剖析 → 受众分析 → 输出 JSON 目录。注入 `{{workDir}}` 和 `{{os}}`。[来源](prompts/outline-system.md#L1-L10)
- **`outline-user.md`** — 用户提示词。实际任务指令：要求 LLM 探索项目、阅读关键文件、生成 JSON 格式的文档目录。注入 `{{workDir}}`、`{{os}}` 和 `{{lang}}`。[来源](prompts/outline-user.md#L1-L10)

### 页面生成阶段（Phase 2）

[`页面生成与并行控制`](页面生成与并行控制.md) 同样使用两个模板配对：

- **`page-system.md`** — 系统提示词。定义 LLM 的角色（"架构分析型技术作者"）和写作规范：Diátaxis 框架、叙事节奏、视觉规范、证据标准。注入 `{{workDir}}`、`{{os}}`、`{{pageTitle}}`、`{{audienceLevel}}`。[来源](prompts/page-system.md#L1-L10)
- **`page-user.md`** — 用户提示词。实际页面编写指令：包含页面元数据（标题、受众、任务描述）和本 Wiki 所有其他页面的交叉引用列表。注入多达 8 个变量，包括 `{{pageTask}}`、`{{availablePages}}`、`{{lang}}` 等。[来源](prompts/page-user.md#L1-L10)

## 模板与代码分离的设计意图

`prompts/` 目录独立于 `src/`，其设计意图非常明确：**开发者可以不修改 TypeScript 代码、不重新编译，直接编辑 Markdown 文件来定制 LLM 行为**。

引擎通过 `PROMPTS_DIR` 解析路径时使用相对定位：

```typescript
const PROMPTS_DIR = resolve(__dirname, '..', '..', 'prompts');
```

`__dirname` 指向 `src/ai/`，两次 `..` 回到项目根目录，再进入 `prompts/`。[来源](src/ai/prompts.ts#L5-L7)

这种设计带来了几个实际好处：

1. **迭代速度**：修改提示词只需编辑 Markdown，无需重启编译链
2. **关注点分离**：代码工程师维护逻辑，技术写作人员优化提示词
3. **可定制性**：用户可以 fork 项目后只修改 `prompts/` 目录，改变生成风格而不触及源码
4. **版本控制友好**：提示词的变更记录在 Git 中独立可见

关于如何编写自定义模板的详细指导，参见 [`编写自定义提示词模板`](编写自定义提示词模板.md)。

## 变量注入的运行时绑定

变量绑定发生在 **调用处**，而非模板定义处。这意味着同一个模板文件，在不同上下文注入不同变量，产出不同的提示词。

以 `generate.ts` 为例，三个关键绑定点：

**大纲系统提示词** — 注入工作目录和操作系统信息：

```typescript
const outlineSysVars = { workDir, os: osInfo };
// osInfo = `${process.platform} ${process.arch}`
// 运行时值如: "win32 x64"
const systemPrompt = await renderPrompt('outline-system.md', outlineSysVars);
```

[来源](src/commands/generate.ts#L131-L132)

**页面系统提示词** — 每个页面循环中注入当前页面标题和受众级别：

```typescript
const pageSysVars = {
  workDir,
  os: osInfo,
  pageTitle: topic.title,     // 如 "提示词模板引擎"
  audienceLevel: topic.level, // 如 "中级"
};
const systemPrompt = await renderPrompt('page-system.md', pageSysVars);
```

[来源](src/commands/generate.ts#L412-L418)

**AI 交互系统提示词** — 注入 Wiki 上下文信息和可用工具列表：

```typescript
const aiSysVars = {
  workDir,
  os: `${process.platform} ${process.arch}`,
  wikiInfo,        // 已生成的 Wiki 内容摘要
  wikiTools: hasWiki ? '### Wiki 工具...' : '（该项目没有 Wiki）',
};
```

[来源](src/commands/ai.ts#L86-L92)

`fillPrompt` 的实现使用 `replace(new RegExp('\\{\\{' + key + '\\}\\}', 'g'), value)`，这意味着：
- 替换是全局的 — 同一个占位符在文本中出现多次会被全部替换
- 值中如果含有 `$` 等特殊字符需要转义（当前实现未做转义处理，使用时需注意）
- 大小写敏感 — `{{workDir}}` 和 `{{workdir}}` 是两个不同的占位符

[来源](src/ai/prompts.ts#L19-L25)
