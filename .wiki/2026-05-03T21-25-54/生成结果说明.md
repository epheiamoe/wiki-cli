# 生成结果说明

当你执行完 `wiki-cli generate` 后，所有生成的文档都存放在项目根目录下的 **`.wiki/`** 文件夹中。理解这个目录的结构，能帮你理解版本管理、断点续传和索引导航的工作原理。

---

## `.wiki/` 目录全景

`.wiki/` 是 wiki-cli 的输出根目录，其下包含两类内容：以时间戳命名的 **版本目录**（每个对应一次完整的生成结果），以及两个有特殊功用的 **内部目录**。下面是一个典型结构：

```
.wiki/
├── 2026-05-03T01-35-03/     ← 第一次生成的版本
│   ├── index.json            ← 目录索引
│   ├── _outline.json         ← 大纲备份
│   ├── 概览.md
│   ├── 快速开始.md
│   └── ...（其他页面）
├── 2026-05-03T19-33-06/     ← 第二次生成的版本（最新）
│   ├── index.json
│   ├── _outline.json
│   ├── 概览.md
│   ├── 快速开始.md
│   └── ...
├── temp/                     ← 生成过程中的临时目录
└── sessions/                 ← AI 问答会话的持久化存储
```

## 版本目录：时间戳即版本号

每次运行 `wiki-cli generate`，系统都会在 `generateCommand()` 函数的最后阶段，将临时目录重命名为一个唯一的时间戳目录。

### 时间戳格式

格式为 **`YYYY-MM-DDTHH-mm-ss`**，由 `getTimestamp()` 函数生成：

```typescript
export function getTimestamp(): string {
  const now = new Date();
  const y = now.getFullYear();
  const M = String(now.getMonth() + 1).padStart(2, '0');
  // ...时、分、秒同理
  return `${y}-${M}-${d}T${h}-${m}-${s}`;
}
```

采用 `T` 替代了标准的冒号（`:`），因为冒号在 Windows 文件系统中是非法字符。排序时直接用字符串的字典序即可：**年→月→日→时→分→秒**，从高位到低位排列，完美自然排序。

### 版本排序逻辑

在 `browseCommand()` 中，系统通过以下方式找到最新版本：

```typescript
const timestamps = entries
  .filter(e => e.isDirectory() && e.name !== 'temp')
  .map(e => e.name)
  .sort()          // 升序：最早→最新
  .reverse();      // 降序：最新在前
```

你可以在 `wiki-cli browse` 时点击右上角的 **"历史版本"** 按钮，从弹窗中选择任意版本浏览。更多细节参见 [版本切换与源代码预览](版本切换与源代码预览.md)。

## 页面文件：每页一个 `.md`

每个版本目录中，除 `index.json` 和 `_outline.json` 外，其余 `.md` 文件都是一个独立的 Wiki 页面。文件名由主题标题自动转换为 **slug**（短横线连接的小写字符串），中文字符会被保留：

```typescript
export function toSlug(title: string): string {
  return title
    .toLowerCase()
    .replace(/[^\w\u4e00-\u9fff]+/g, '-')  // 保留中文
    .replace(/^-+|-+$/g, '')               // 去掉首尾横线
    || 'untitled';
}
```

因此 `概览` → `概览.md`，`LLM 提供商与模型选择` → `llm-提供商与模型选择.md`。

## `index.json`：目录索引即导航数据

`index.json` 是整个 Wiki 的 **目录骨架**。浏览器端侧边栏导航、页面列表都依赖它生成。由 `generateIndex()` 函数在生成完成后自动写入。

### JSON Schema

```json
{
  "sections": [
    {
      "name": "入门指南",
      "topics": [
        {
          "level": "初学",
          "title": "概览",
          "description": "项目定位、核心功能与设计理念概述...",
          "task": "阅读 README.md 和 src/cli.ts..."
        },
        {
          "type": "group",
          "title": "核心用法"
        }
      ]
    }
  ]
}
```

**字段说明**：

| 字段 | 存在条件 | 含义 |
|------|----------|------|
| `sections` | 必有 | 顶层分组，由 LLM 生成大纲时定义 |
| `sections[].name` | 必有 | 章节名称 |
| `sections[].topics` | 必有 | 该章节下的主题列表 |
| `topics[].type` | `"group"` 时 | 标记为分组标题（不可点击，仅用于视觉分隔） |
| `topics[].level` | 非 group | 受众水平：`初学` / `中级` / `高级` |
| `topics[].title` | 必有 | 页面标题 |
| `topics[].description` | 可选 | 简述该页内容 |
| `topics[].task` | 可选 | LLM 生成该页面的写作任务指令 |

`index.json` 由 `generateIndex()` 从程序内部维护的 `Topic[]` 数组序列化而来，核心逻辑仅 20 行：

```typescript
async function generateIndex(wikiDir: string, topics: Topic[]): Promise<void> {
  const jsonOut = { sections: [] };
  const sections = [...new Set(topics.map(t => t.section).filter(Boolean))];
  for (const section of sections) {
    // ...按 section 分组，组装 topics
  }
  await writeTextFile(join(wikiDir, 'index.json'), JSON.stringify(jsonOut, null, 2));
}
```

## `_outline.json`：大纲快照

每个版本目录中都有 `_outline.json`，它是 **Phase 1（大纲生成阶段）的输出快照**。在 `generateOutline()` 成功解析出 JSON 大纲后，会将原始 LLM 回复（包含代码围栏）原样写入临时目录 `_outline.json`：

```typescript
await writeTextFile(join(TEMP_DIR, '_outline.json'), fullContent);
```

当生成完成、临时目录移入版本目录时，`_outline.json` 也随之迁入。它的主要用途是：

- **调试辅助**：查看 LLM 最初生成的大纲原始内容，对比最终版本，评估提示词效果。
- **元信息存档**：大纲中包含每个页面的 `task`（写作任务），这对于理解页面为何如此编写有参考价值。

大纲的生成细节参见 [大纲生成阶段](大纲生成阶段.md)。

## 特殊目录：`.wiki/temp` 与 `.wiki/sessions`

这两个目录不对外展示，是工具的内部工作区。

### `.wiki/temp`：断点续传的检查点

生成过程中，所有页面文件（`.md`）和 `_outline.json` 先写入 `.wiki/temp/`。只有全部完成后，才通过 `moveDir(TEMP_DIR, finalDir)` 整体重命名为最终版本目录。

每次重新运行 `wiki-cli generate` 时，系统会检测 `temp/` 是否存在：

- **存在** → 询问用户：**Resume**（跳过已生成的页面继续）或 **Fresh**（删除重新开始）。
- **不存在** → 创建新 `temp/` 开始生成。

这意味着即便生成到一半中断（网络断开、终端关闭），只要 `temp/` 还在，就可以从中断处继续。参见 [断点续传与重试机制](断点续传与重试机制.md)。

[来源: temp 检测与 Resume/Fresh 选择](generate.ts#L29-L43) | [来源: 最终 moveDir](generate.ts#L143-L145)

### `.wiki/sessions`：AI 问答会话库

当使用 `wiki-cli ai` 命令进行交互式问答时，每次对话都会被持久化为一个 JSON 文件，存放在 `.wiki/sessions/` 目录下。每个会话文件以 **8 字符 UUID** 命名：

```
.wiki/sessions/
├── 1c9f5d29.json
├── 549a3e02.json
├── 7d6654ea.json
└── 9961c13f.json
```

每个 JSON 文件的结构如下：

```json
{
  "id": "1c9f5d29",
  "created": "2026-05-03T12:30:00.000Z",
  "updated": "2026-05-03T12:35:22.000Z",
  "summary": "如何添加新的 LLM 提供商？",
  "messages": [
    { "role": "user", "content": "..." },
    { "role": "assistant", "content": "..." }
  ]
}
```

会话管理支持创建、列表、加载、删除和切换操作。详细用法参见 [AI 交互命令：wiki-cli ai](ai-交互命令-wiki-cli-ai.md)。
