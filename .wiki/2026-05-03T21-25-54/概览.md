# 概览

**Wiki CLI** 是一个命令行工具，它能自动分析你本地的代码仓库，借助 **大语言模型（LLM）** 生成结构化的 Wiki 文档。你不需要手动写一行文档——工具会替你读完代码、规划目录结构、逐页生成内容，最终交付一份可在浏览器中阅读的完整 Wiki。

## 核心价值

绝大多数开发者面临同一个矛盾：代码写得越多，越没时间写文档。Wiki CLI 的解决思路很直接——让 LLM 充当"文档工程师"。你只需运行一条命令，它就会：

1. 扫描仓库的文件结构，了解项目全貌
2. 通过 Function Calling 机制调用只读工具（如读取文件、列出目录），深入理解代码逻辑
3. 输出一份结构清晰的多页 Wiki，保存在项目本地

整个过程你不需要联网以外的任何基础设施，生成的文档完全归你所有，随意修改和分享。

## 四条命令的功能定位

工具提供了四个子命令，分别对应**配置 → 生成 → 浏览 → 交互**的完整工作流：

| 命令 | 功能定位 | 典型使用场景 | 交互方式 |
|------|----------|-------------|----------|
| `wiki-cli config` | 配置 LLM 提供商、模型、API 密钥和文档语言 | 首次使用或更换模型时 | 交互式提示 + 命令行参数 |
| `wiki-cli generate` | 分析当前仓库，分两阶段生成 Wiki 文档 | 日常生成或更新文档 | 自动执行 + 流式输出进度 |
| `wiki-cli browse` | 在本地启动 HTTP 服务，浏览器中浏览生成的 Wiki | 查阅最新生成的文档 | 自动打开浏览器 |
| `wiki-cli ai` | 交互式 AI 问答，可结合 Wiki 和源码与 LLM 讨论代码 | 深入理解代码细节 | 命令行对话 + 会话管理 |

[来源](src/cli.ts#L17-L60)

### 命令间的关系

四条命令构成了一个清晰的管线：先用 `config` 配好 LLM 访问凭证，然后用 `generate` 生成文档，用 `browse` 阅读结果。`ai` 命令则是一个"加餐"——它让你在生成的 Wiki 基础上，与 LLM 自由对话，深入探讨代码的某一部分。

更多细节见各命令的专门页面：[配置命令](配置命令-wiki-cli-config.md)、[生成命令](生成命令-wiki-cli-generate.md)、[浏览命令](浏览命令-wiki-cli-browse.md)、[AI 交互命令](ai-交互命令-wiki-cli-ai.md)。

## 关键特性

**跨平台运行**  
工具使用纯 Node.js 编写，在 Windows、macOS、Linux 上均可无差别运行。只需 Node.js >= 18 即可。  
[来源](package.json#L24-L26)

**流式输出**  
生成过程中，LLM 的回复会逐字流式打印到终端。你不需要盯着空白屏幕等待——每一步正在做什么、LLM 正在输出什么，一目了然。  
[来源](src/commands/generate.ts#L255-L259)

**断点续传**  
生成过程因网络中断、API 超时等原因意外停止后，重新运行 `wiki-cli generate` 会检测到临时目录 `.wiki/temp`，询问你是从上次检查点**恢复**还是**重新开始**。即使遇到暂时失败的单页，也会自动进入重试循环，直到所有页面生成完毕。  
[来源](src/commands/generate.ts#L36-L52)

**并行生成模式**  
第二阶段逐页生成时，你可以选择串行（流式输出，便于观察）或**并行**（指定 1-10 的并发数，速度更快）。需要质量观察选串行，追求速度选并行。  
[来源](src/commands/generate.ts#L71-L84)

**多 LLM 提供商支持**  
内置 7 家 LLM 提供商共 21 个模型，从 OpenAI 到 DeepSeek、Anthropic、Google Gemini 等，也支持自定义提供商。详见 [LLM 提供商与模型选择](llm-提供商与模型选择.md)。

**版本化管理**  
每次生成的 Wiki 保存在 `.wiki/<时间戳>/` 目录下，互不覆盖。浏览时可切换历史版本，也支持在线预览源码文件。详见 [生成结果说明](生成结果说明.md) 和 [版本切换与源代码预览](版本切换与源代码预览.md)。

## 技术栈

| 技术 | 用途 |
|------|------|
| **TypeScript** | 全项目使用，类型安全，编译为 CommonJS/ESM 模块 |
| **Commander.js** | 命令行框架，注册命令、解析参数、自动生成帮助信息 |
| **Inquirer** | 交互式提示，用于配置向导和生成过程中的用户选择 |
| **Marked** | Markdown 渲染，将生成的 .md 文件转为 HTML |
| **Highlight.js** | 代码语法高亮，在浏览页面中美观呈现代码片段 |
| **chalk** | 终端彩色输出，区分信息/成功/警告/错误消息 |
| **ora** | 终端 spinner，在长时间操作时显示加载动画 |

[来源](package.json#L13-L22)

源码采用**四模块架构**：CLI 入口 → 命令层 → AI 层 → 工具库，各模块职责清晰。详见 [整体架构与模块划分](整体架构与模块划分.md)。

## 适用场景

- **个人项目**：快速产出基本文档，省去手动撰写的时间
- **团队交接**：为新成员提供一份可读的代码库概览
- **开源项目**：补充或更新 README 以外的结构化文档
- **代码审计**：让 LLM 先"通读"一遍代码，输出结构摘要再人工审查

如果你正在寻找一种低成本、自动化的方式为任意代码仓库生成文档，Wiki CLI 值得一试。
