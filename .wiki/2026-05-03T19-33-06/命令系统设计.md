命令系统是 wiki-cli 的入口骨架，它决定了用户如何与整个工具交互。这一层很薄——职责仅限于"接收参数、分发到具体实现、兜底异常"，不包含业务逻辑。

## 入口层：Commander.js 的链式注册

入口文件 `src/cli.ts` 使用 **Commander.js**（v12.1.0）构建 CLI，采用典型的链式调用模式：

```typescript
const program = new Command();

program
  .name('wiki-cli')
  .description('Auto-generate structured Wiki documentation for any local code repository')
  .version('1.0.0');

program
  .command('config')
  .description('Interactive configuration of LLM provider, model, API key, language')
  .option('--provider <provider>', 'LLM provider name')
  // ...更多选项
  .action(async (options) => { /* ... */ });
```

链式的本质是 **每个方法都返回 `this`**，使得命令注册、选项绑定、行为定义可以在一个连续表达式中完成。四条命令的注册结构完全一致：`program.command(name).description(...).options/arguments(...).action(handler)`。

注册顺序决定了 `--help` 输出中命令的排列顺序：**config → generate → browse → ai**，这恰好反映了典型工作流——先配置、再生成、再浏览、最终深入代码。

最后，当用户未传入任何参数时，自动打印帮助信息：

```typescript
if (!process.argv.slice(2).length) {
  program.outputHelp();
}
```

## 四条命令的职责边界

每个命令独立为一个模块，位于 `src/commands/` 目录。以下是它们的职责边界与依赖关系：

### config —— 配置管理

**职责**：引导用户完成 LLM 提供商、模型、API Key、语言等配置的交互式设置。支持命令行参数直传（跳过交互）和交互式问答两种模式。

**核心依赖**：
- `config-store.ts` —— 配置的加载、保存、模型清单查询
- `progress.ts` —— 日志输出

**关键行为**：当所有必要参数通过 `--provider --base-url --model --api-key` 提供时，直接保存并退出；否则启动 `inquirer` 交互式向导。

[来源](src/commands/config.ts#L1-L13)

### generate —— 核心生成

**职责**：分析当前仓库，经两阶段流程（大纲生成 + 页面生成）生成完整 Wiki 文档。

**核心依赖**：
- `config-store.ts` —— 读取 LLM 配置
- `llm-client.ts` —— 与 AI 通信
- `prompts.ts` —— 渲染提示词模板
- `tools.ts` —— 执行代码探索工具调用
- `file.ts` —— 文件与目录操作

这是四条命令中**最复杂**的一条，内部包含完整的 `collectFullResponse` 循环（支持工具调用链、流式输出），以及断点续传、并行生成、失败重试等机制。详见 [生成 Wiki 文档](生成-wiki-文档.md) 和 [两阶段生成流程](两阶段生成流程.md)。

[来源](src/commands/generate.ts#L1-L49)

### browse —— 本地服务

**职责**：启动本地 HTTP 服务器，在浏览器中浏览已生成的 Wiki 内容。

**核心依赖**：
- `node:http` —— 纯 Node.js HTTP 服务器
- `marked` —— Markdown 渲染
- `progress.ts` —— 日志输出

**独特之处**：这是唯一**不依赖 AI 模块**的命令。它通过 `findFreePort` 自动寻找可用端口，并尝试使用系统命令（`start`/`open`/`xdg-open`）打开浏览器。内置了完整的 SPA 单页应用 HTML。

详见 [本地 HTTP 服务器实现](本地-http-服务器实现.md) 和 [浏览器端 SPA 体验](浏览器端-spa-体验.md)。

[来源](src/commands/browse.ts#L1-L28)

### ai —— 智能对话

**职责**：与 AI 进行交互式对话，支持多轮会话管理、代码探索工具调用。

**核心依赖**：
- `llm-client.ts` —— AI 通信
- `prompts.ts` —— 提示词渲染
- `tools.ts` —— 工具调用执行
- `ai-session.ts` —— 会话持久化与管理
- `generate.ts` —— 在有需要时动态导入生成命令

**独特之处**：
- 支持 `wiki-cli ai "一个问题"` 单次问答模式和 `wiki-cli ai` 交互式 REPL 模式
- 交互式模式下包含完整的斜杠命令系统（`/save`, `/sessions`, `/switch`, `/wiki` 等）
- 可动态检测是否有已生成的 Wiki，无时邀请用户先生成

详见 [AI 问答交互](ai-问答交互.md) 和 [交互式 AI 会话管理](交互式-ai-会话管理.md)。

## 全局错误处理：统一兜底策略

每个命令的 `action` 回调都遵循相同的模式：

```typescript
.action(async (options) => {
    try {
      await configCommand(options);
    } catch (err: any) {
      logError(err.message);
      process.exit(1);
    }
  });
```

这个模式的三个要点：

1. **`try-catch` 包裹**：确保所有未预期的异常不会导致静默失败或悬空的 Promise。
2. **`logError(err.message)`**：使用 `chalk.red('✖')` 格式化输出错误信息，而非直接 `console.error`。
3. **`process.exit(1)`**：立即终止进程，退出码为 1，避免在错误状态下继续执行。

`logError` 函数来自 [`src/utils/progress.ts`](src/utils/progress.ts#L18-L20)，定义十分简洁：

```typescript
export function logError(msg: string): void {
  console.log(chalk.red('✖'), msg);
}
```

此外，`generate` 和 `ai` 命令内部还有**两层额外的错误处理**：命令模块内部在检测到前置条件不满足（如未配置、未生成 Wiki）时，会自动调用 `logError` 并 `process.exit(1)`，而不是将错误抛回给 `cli.ts`。

从依赖关系可以看出一个**清晰的分层结构**：

- **CLI 入口层**：`cli.ts` — 只依赖命令模块和日志工具

- **服务层**：`config/`, `ai/`, `utils/` — 无相互依赖，各自独立
