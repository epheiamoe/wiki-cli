# 源代码浏览功能

在本地浏览 Wiki 时，除了阅读生成的文档页面，你还能直接跳转到源码文件查看原始代码——带语法高亮、语言检测和路径安全过滤。这个功能让文档与源代码之间的双向引用成为可能：文档中标记的 `[来源：src/commands/browse.ts]` 链接，点击后直接在新标签页打开高亮渲染的源码。

## 路由分发：`/api/source/`

源码浏览功能是 HTTP 服务器的一个独立路由，路径模式为 `/api/source/{文件路径}`。当浏览器访问这个路径时，服务器执行以下流程：

1. **解码路径**：`decodeURIComponent` 还原 URL 编码的路径字符串
2. **安全过滤**：`sanitizePath` 阻止目录穿越攻击
3. **文件读取**：以项目根目录为基准，读取目标文件内容
4. **语言检测**：根据文件扩展名映射到 highlight.js 语言标识
5. **HTML 渲染**：内联生成一个完整的源码浏览页面

[来源](browse.ts#L76-L113)

## 安全过滤：sanitizePath

> 一切用户提供的路径在用于文件系统之前，都必须经过杀菌处理。

`sanitizePath` 函数是源码浏览功能的第一道防线。它的实现包含三层防护：

```typescript
function sanitizePath(rawPath: string): string | null {
  const cleaned = rawPath.replace(/^[/\\\\]+/, '');          // ① 去掉前导斜杠
  const normalized = normalize(cleaned)
    .replace(/^(\\.\\.(\\/|\\\\))+/g, '');                   // ② 解析并剥离前导的 ..
  const resolved = resolve(PROJECT_ROOT, normalized);        // ③ 解析为绝对路径
  if (!resolved.startsWith(PROJECT_ROOT + sep) 
      && resolved !== PROJECT_ROOT) return null;             // ④ 确认仍在项目根目录内
  return normalized;
}
```

| 层级 | 操作 | 目的 |
|------|------|------|
| ① 前缀清理 | 移除开头的 `/` 或 `\` | 防止将绝对路径解析为系统根目录 |
| ② 归一化 | `normalize` + 剥离前导 `..` | 消除路径中的 `.` 和 `..` 段 |
| ③ 绝对化 | `resolve(PROJECT_ROOT, ...)` | 将相对路径解析为绝对路径 |
| ④ 边界检查 | `startsWith(PROJECT_ROOT)` | 确认解析后的路径仍在项目目录内 |

如果任何一层检查失败，函数返回 `null`，服务器立即响应 **403 Forbidden**。这意味着攻击者无法通过 `../../etc/passwd` 之类的路径逃离项目目录。

## 扩展名到语言标识的映射

`extToLang` 函数维护了一张从文件扩展名到 highlight.js 语言标识的映射表：

```typescript
function extToLang(ext: string): string {
  const map: Record<string, string> = {
    '.ts': 'typescript', '.js': 'javascript', '.json': 'json',
    '.md': 'markdown', '.yml': 'yaml', '.yaml': 'yaml',
    '.html': 'html', '.css': 'css', '.sh': 'bash', '.bash': 'bash',
  };
  return map[ext] || 'plaintext';
}
```

映射表覆盖了该项目最常用的文件类型：TypeScript、JavaScript、JSON、Markdown、YAML、HTML、CSS 和 Shell 脚本。对于未在表中注册的扩展名（如 `.svg`、`.txt`），默认回退为 `plaintext`，确保至少显示无高亮的纯文本。

这个映射在生成 HTML 时被两处使用：一是 `language-${lang}` CSS class 供 highlight.js 识别，二是在页面头部的语言徽章中展示。

[来源](browse.ts#L265-L269)

## 源码 HTML 页面布局

生成的源码浏览页面是一个自包含的 HTML 文档，布局分为三个区域：

```
┌─────────────────────────────────────────────┐
│  ← Wiki  |  src/commands/browse.ts    [ts]  │  ← 固定头部（sticky）
├─────────────────────────────────────────────┤
│                                             │
│  import { readFile, readdir }               │
│  import { join, extname, resolve }          │
│  ...                                        │  ← <pre><code> 代码块
│                                             │
│  function sanitizePath(rawPath) { ... }     │
│  function extToLang(ext) { ... }            │
│                                             │
└─────────────────────────────────────────────┘
```

### 固定头部

头部使用 `position: sticky; top: 0; z-index: 10` 固定在视口顶部，包含三个元素：

- **← Wiki 返回按钮**：链接到 `/?version={当前版本}`，点击回到主浏览界面
- **文件路径**：`<span class="path">` 显示完整的文件路径，等宽字体渲染
- **语言徽章**：右侧自动对齐的灰色标签，显示 `extToLang` 检测到的语言名称（如 `typescript`、`markdown`）

### 代码块

主体部分是一个标准的 `<pre><code class="language-...">` 结构，内容经过 `escapeHtml` 转义（`&` → `&amp;`，`<` → `&lt;`，`>` → `&gt;`，`"` → `&quot;`）。转义是必须的——如果不转义，源码中的 HTML 标签会被浏览器解析破坏页面结构。

[来源](browse.ts#L86-L106)

## CDN 资源加载策略

highlight.js 的资源通过 CDN 按需加载，不打包到服务器代码中：

```html
<!-- head 中加载主题样式 -->
<link rel="stylesheet" href="https://cdnjs.cloudflare.com/ajax/libs/
  highlight.js/11.9.0/styles/github-dark.min.css">

<!-- body 末尾加载库本体 -->
<script src="https://cdnjs.cloudflare.com/ajax/libs/
  highlight.js/11.9.0/highlight.min.js"></script>

<!-- 触发高亮 -->
<script>hljs.highlightAll();</script>
```

这种策略有两层考量：

1. **体积优化**：highlight.js 完整包约数百 KB，不嵌入服务器代码可以减少项目依赖，加快 `npm install`
2. **缓存友好**：CDN 资源跨站点共享浏览器缓存，用户访问多个使用相同 CDN 链接的站点时无需重复下载

风险在于**离线不可用**——如果用户在没有网络连接的环境下浏览，源码页面将无法获得高亮样式和语法着色。这是权衡开发体验与运行时可靠性的一个取舍点。所有 CDN 资源都使用固定的版本号 `11.9.0`，避免未来 CDN 发布破坏性更新导致页面异常。

[来源](browse.ts#L93-L108)

## HTML 转义与安全

除了路径安全，代码内容展示也需要防范 XSS。`escapeHtml` 函数对文件内容执行四次替换：

```typescript
function escapeHtml(text: string): string {
  return text.replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;');
}
```

`&` 的替换必须放在第一位——否则像 `&lt;` 中的 `&` 会被二次转义为 `&amp;lt;`。经过转义后，源码中的任何 HTML 标签都成为纯文本，浏览器不会将其解释为 DOM 元素。
