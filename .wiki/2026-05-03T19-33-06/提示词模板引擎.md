# 提示词模板引擎

**提示词模板引擎**是 wiki-cli 中将 LLM 提示词从代码中解耦的核心机制。它将全部提示词外置为 `prompts/` 目录下的 Markdown 文件，通过三级函数实现模板加载、变量替换与渲染，使得优化提示词不再需要修改源码，让领域专家也能直接参与提示工程。

## 架构：三级函数链路

引擎由 `src/ai/prompts.ts` 中三个导出的函数组成，形成一条清晰的调用链：

```
loadPrompt(filename) → 读取 .md 文件
        ↓
fillPrompt(template, vars) → 替换 {{var}} 占位符
        ↓
renderPrompt(filename, vars) → 组合以上两步
```

### 第一级：loadPrompt

从文件系统加载原始模板。通过 `import.meta.url` 推导 `prompts/` 目录的绝对路径（`PROMPTS_DIR`），再拼接传入的文件名读取 UTF-8 内容。这是一个异步函数，返回 `Promise<string>`。

```typescript
const PROMPTS_DIR = resolve(__dirname, '..', '..', 'prompts');

export async function loadPrompt(filename: string): Promise<string> {
  const fullPath = join(PROMPTS_DIR, filename);
  return readFile(fullPath, 'utf-8');
}
```

[来源](../src/ai/prompts.ts#L8-L17)

### 第二级：fillPrompt

纯函数式的模板替换。接收模板字符串和 `PromptVars`（键值均为 `string` 的简单对象），对每个变量键构建正则表达式 `/\{\{key\}\}/g`，进行全局替换。

```typescript
export function fillPrompt(template: string, vars: PromptVars): string {
  let result = template;
  for (const [key, value] of Object.entries(vars)) {
    result = result.replace(new RegExp(`\\{\\{${key}\\}\\}`, 'g'), value);
  }
  return result;
}
```

[来源](../src/ai/prompts.ts#L19-L25)

关键设计决策：使用 `g` 标志实现**同一变量多处替换**；对未提供的变量**保持原样**而不报错。后者是一种宽容设计——允许模板包含可选变量，在未提供时其占位符仍然可见，方便调试。单测覆盖了这些边界情况：

| 场景 | 输入 | 预期行为 |
|------|------|----------|
| 单变量替换 | `{{name}}` → `World` | `Hello World` |
| 多变量替换 | `{{x}} + {{x}} = {{y}}` | `2 + 2 = 4` |
| 未提供变量 | `{{name}}` 无 vars | `{{name}}` 保留 |
| 中文值 | `{{lang}}` → `中文` | `语言：中文` |

[来源](../tests/prompts.test.ts#L5-L40)

### 第三级：renderPrompt

组合前两级，暴露给调用方的最常用接口。调用方只需指定文件名和变量字典，即可一步完成加载与渲染：

```typescript
export async function renderPrompt(filename: string, vars: PromptVars): Promise<string> {
  const template = await loadPrompt(filename);
  return fillPrompt(template, vars);
}
```

[来源](../src/ai/prompts.ts#L27-L30)

## prompts/ 目录：五份提示词文件

`prompts/` 目录下共 5 个 Markdown 文件，按用途分为三组：

```
prompts/
├── outline-system.md     ← 大纲生成阶段：系统提示
├── outline-user.md       ← 大纲生成阶段：用户提示
├── page-system.md        ← 页面生成阶段：系统提示
├── page-user.md          ← 页面生成阶段：用户提示
└── ai-system.md          ← AI 对话模式：系统提示
```

### 大纲生成：outline-system.md + outline-user.md

在 [两阶段生成流程](两阶段生成流程.md) 的**第一阶段**被调用。生成命令会先后渲染这两个文件：

- `outline-system.md`：定义 LLM 的角色——兼具软件工程师与技术文档专家的双重身份。提供分析框架（高层愿景→架构剖析→受众分析），并要求输出严格的 JSON 格式目录。模板变量包括 `{{workDir}}`、`{{os}}`。
- `outline-user.md`：给 LLM 的具体任务指令，包含项目元数据（目录、操作系统、语言），指示其探索代码后生成 JSON 目录。

调用点（`src/commands/generate.ts`）：

```typescript
const systemPrompt = await renderPrompt('outline-system.md', outlineSysVars);
const userPrompt   = await renderPrompt('outline-user.md',   outlineUserVars);
```

[来源](../src/commands/generate.ts#L131-L132)

### 页面生成：page-system.md + page-user.md

在[两阶段生成流程](两阶段生成流程.md)的**第二阶段**被调用。针对每个待生成页面，生成命令为每个主题渲染一次：

- `page-system.md`：定义写作角色的系统提示——"架构分析型技术作者"，要求采用 Diátaxis 框架组织内容、在每段结尾标注来源、使用交叉引用。模板变量包括 `{{workDir}}`、`{{os}}`、`{{pageTitle}}`、`{{audienceLevel}}`。
- `page-user.md`：包含该页面的具体编写任务，如项目元数据、本页编写任务说明、所有可用页面列表（供交叉引用）。模板变量包括 `{{workDir}}`、`{{pageTitle}}`、`{{audienceLevel}}`、`{{pageSlug}}`、`{{projectSummary}}`、`{{pageTask}}`、`{{availablePages}}`。

调用点：

```typescript
const systemPrompt = await renderPrompt('page-system.md', pageSysVars);
const userPrompt   = await renderPrompt('page-user.md',   pageUserVars);
```

## 设计优势：提示词外置

将提示词外置为独立的 Markdown 文件，带来了三个核心收益：

1. **零代码修改优化**：改善提示词的措辞、补充示例、调整输出格式，都只需修改 `prompts/` 下的 `.md` 文件。不需要重新编译 TypeScript、不需要接触代码逻辑。这使得非开发者的提示工程师也能独立参与。

2. **模板变量驱动的动态上下文**：`{{workDir}}` 注入当前项目路径，`{{os}}` 传递操作系统信息，`{{pageTitle}}` 和 `{{audienceLevel}}` 定制页面写作参数。模板在渲染时注入运行时上下文，一份提示词模板即可适配不同项目和场景。

3. **关注点分离**：提示词的内容策略与代码的执行逻辑完全解耦。`src/ai/prompts.ts` 只关心"如何加载和渲染"，不关心"提示词说了什么"；`prompts/*.md` 只关心"写什么"，不关心"谁在调用"。
