# 配置存储与模型清单

当用户运行 `wiki-cli config` 交互式配置时，工具需要解决两个核心问题：

1. **用户配置持久化** —— 将 API Key、模型选择等写入本地文件系统
2. **内置模型数据库** —— 为已知 LLM 提供商预置 endpoint、模型名和定价提示

这两个问题由 `src/config/config-store.ts` 和 `src/config/default-models.json` 共同解决。

---

## 配置文件路径的跨平台设计

配置的根目录和文件路径在模块加载时就确定下来：

```typescript
const CONFIG_DIR = join(homedir(), '.wiki-cli');
const CONFIG_PATH = join(CONFIG_DIR, 'config.json');
```

`homedir()` 来自 `node:os` 模块，在主流操作系统上的解析行为如下：

| 操作系统 | 解析路径 |
|---|---|
| Linux / macOS | `~/.wiki-cli/config.json`（即 `$HOME/.wiki-cli/config.json`） |
| Windows | `C:\Users\<用户名>\.wiki-cli\config.json`（即 `%USERPROFILE%\.wiki-cli\config.json`） |

这种设计有几点意图：

- **避免污染项目工作目录**：配置独立于任何特定仓库，用户只需配置一次即可在所有项目中使用。
- **无需管理员权限**：用户主目录下的 `.wiki-cli` 目录由 `saveConfig` 自动创建（通过 `mkdir` 的 `recursive: true` 参数），无需 `sudo`。
- **符合 XDG Base Directory 的简化版精神**：虽然没有使用 `$XDG_CONFIG_HOME`，但对 CLI 工具而言，`~/.<tool-name>` 是社区最广泛接受的惯例（类似 `.gitconfig`、`.npmrc`、`.aws` 等）。

`getConfigDir()` 和 `getConfigPath()` 两个导出函数将路径暴露给外部——例如 `config` 命令在保存成功后打印文件路径：[配置你的 LLM 提供商](配置你的-llm-提供商.md)。[来源](../src/config/config-store.ts#L24-L46)

## 配置文件的读写契约

**`WikiCliConfig` 接口**定义了持久化的数据结构：

```typescript
export interface WikiCliConfig {
  provider: string;
  baseUrl: string;
  model: string;
  apiKey: string;
  lang: string;
  jsonMode?: boolean;
}
```

`loadConfig()` 和 `saveConfig()` 是对 JSON 文件的序列化/反序列化封装，值得注意的细节：

- `loadConfig` 在文件不存在或解析失败时返回 `null`，而非抛出异常 —— 这是 CLI 工具中常见的"宽容读取"模式，允许首次使用时不预置任何配置。
- `saveConfig` 在写入前确保目录存在（`mkdir({ recursive: true })`），无需预先创建 `.wiki-cli` 目录。
- `apiKey` 以明文存储 —— 这是一个已知的权衡。更安全的方案（如系统密钥链、加密存储）超出当前版本的范围。[来源](../src/config/config-store.ts#L48-L61)

## ModelEntry 接口与 JSON 数据源

内置模型清单来自 `default-models.json`，加载时通过 `import` 语句直接导入为类型化数组：

```typescript
import defaultModels from './default-models.json' with { type: 'json' };
```

每个模型对应一个 **`ModelEntry`** 记录：

```typescript
export interface ModelEntry {
  provider: string;      // 提供商分组名称
  model: string;         // 模型标识符（如 "gpt-5.5"）
  baseUrl: string;       // API endpoint
  description: string;   // 人类可读描述
  pricingHint?: string;  // 价格提示（可选，用于终端交互中辅助选择）
}
```

`loadDefaultModels()` 是一个简单的类型转换函数，将 JSON 数据以 `ModelEntry[]` 形式返回。这种方式的好处是：JSON 数据源可以被外部工具编辑，也可以在未来通过远程拉取更新。[来源](../src/config/config-store.ts#L14-L22)

## supportsJsonMode：已知提供商 vs Custom 的三态逻辑

JSON mode（即 `response_format: { type: "json_object" }`）是 OpenAI 兼容 API 的可选能力。`supportsJsonMode` 函数返回 **三态值**，而非简单的布尔值：

```typescript
const JSON_MODE_PROVIDERS = new Set([
  'OpenAI',
  'DeepSeek',
  'xAI Grok',
  'Mistral',
  'Kimi (Moonshot)',
]);

export function supportsJsonMode(provider: string): boolean | undefined {
  if (provider === 'Custom') return undefined; // unknown, ask user
  return JSON_MODE_PROVIDERS.has(provider);
}
```

含义清晰：

| 返回值 | 含义 | 处理逻辑 |
|---|---|---|
| `true` | 已知支持 JSON mode | 自动启用，不询问用户 |
| `false` | 已知不支持（如 Google Gemini、Anthropic） | 自动关闭，不询问用户 |
| `undefined` | 未知（Custom 提供商） | **交互式询问**用户是否支持 |

在 `config` 命令中，当 `supportsJsonMode` 返回 `undefined` 时，会弹出 confirm 提示："Does this provider support JSON output mode?"。[来源](../src/config/config-store.ts#L27-L37)

## 过滤逻辑：getProviders 与 getModelsByProvider

这两个纯函数将 `ModelEntry[]` 转换为 UI 可用的数据结构：

**`getProviders`** 提取去重后的提供商列表：

```typescript
export function getProviders(models: ModelEntry[]): string[] {
  const providers = new Set(models.map(m => m.provider));
  return [...providers];
}
```

它保证每个提供商在列表中只出现一次，且顺序由首次出现次序决定（`Set` 的迭代顺序保持插入顺序）。这个列表被 `config` 命令用于 `inquirer` 的下拉选择器。

**`getModelsByProvider`** 按提供商筛选模型，用于当用户选择了某个提供商后，展示该提供商下的模型供选择：

```typescript
export function getModelsByProvider(models: ModelEntry[], provider: string): ModelEntry[] {
  return models.filter(m => m.provider === provider);
}
```

在 `config` 命令中，筛选后的模型列表被渲染为带描述的选项：

```
gpt-5.5 - OpenAI GPT-5.5 (latest flagship) (Most expensive, highest quality)
gpt-5.4 - OpenAI GPT-5.4 (High quality, lower cost than 5.5)
...
```

如果你选择了 `__custom__` 入口，则绕过内置列表，直接由用户手动输入 `baseUrl` 和 `model`。[来源](../src/commands/config.ts#L8-L80)

## 配置字段与 JSON 映射速查

下表列出 `WikiCliConfig` 字段与最终 `config.json` 的映射关系：

| 接口字段 | JSON key | 数据类型 | 说明 |
|---|---|---|---|
| `provider` | `provider` | string | 提供商名称，或 `"Custom"` |
| `baseUrl` | `baseUrl` | string | API 基础 URL |
| `model` | `model` | string | 模型标识符 |
| `apiKey` | `apiKey` | string | API 密钥（明文） |
| `lang` | `lang` | string | 文档语言，`"zh"` 或 `"en"` |
| `jsonMode` | `jsonMode` | boolean (可缺省) | 是否使用 `response_format: json_object` |

生成的 `~/.wiki-cli/config.json` 示例：

```json
{
  "provider": "OpenAI",
  "baseUrl": "https://api.openai.com/v1",
  "model": "gpt-5.4-mini",
  "apiKey": "sk-...",
  "lang": "zh",
  "jsonMode": true
}
```

## 设计要点回顾

- **跨平台路径**：`homedir()` 确保 Windows/macOS/Linux 的一致性，`mkdir recursive` 消除目录预创建负担。
- **存储即 JSON**：配置与模型数据均使用无 schema 的 JSON 文件，零外部依赖，人类可直接编辑。
- **三态 JSON mode 检测**：`supportsJsonMode` 的 `true / false / undefined` 设计，准确区分"已知支持"、"已知不支持"和"未知需询问"三种场景。
- **纯函数过滤**：`getProviders` / `getModelsByProvider` 无副作用，输入 `ModelEntry[]` 输出 UI 所需结构，易于测试。
