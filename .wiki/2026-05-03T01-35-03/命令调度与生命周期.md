# 命令调度与生命周期

`cli.ts` 是 wiki-cli 的进程入口点。它不参与任何业务逻辑——只做三件事：装配 Commander.js 路由表、将系统控制权交给匹配的命令、在命令结束后善后（异常退出或强制退出）。理解这个文件等于理解整个工具的生命周期骨架。

---

## Commander.js 编程式 API

入口文件使用 Commander.js 的**编程式 API**，而非解析 `process.argv` 原始字符串。核心是创建一个 `Command` 实例，链式填充元数据：

```typescript
const program = new Command();
program
  .name('wiki-cli')
  .description('Auto-generate structured Wiki documentation for any local code repository')
  .version('1.0.0');
```

- `.name()` 定义帮助信息中的工具名称
- `.description()` 定义一行摘要
- `.version()` 注册 `--version` / `-V` 标志

这三个方法不产生副作用，只修改 `program` 对象的内部状态，等待 `program.parse(process.argv)` 触发路由。

## 三命令路由表

`program` 上注册了三个子命令，每个都使用相同的链式模式：`.command().description().action()`。

| 命令 | 说明 | 实现模块 |
|------|------|----------|
| `config` | 交互式配置 LLM 提供商、模型、API Key、语言 | [config.ts](../src/commands/config.ts) |
| `generate` | 分析当前仓库并生成 Wiki 文档 | [generate.ts](../src/commands/generate.ts) |
| `browse` | 在浏览器中打开已生成的 Wiki | [browse.ts](../src/commands/browse.ts) |

**config** 命令额外接受五个可选 `--option` 参数，允许完全跳过交互式向导直接保存配置。

[来源](../src/cli.ts#L14-L56)

## 异常处理：统一的 `try-catch` 屏障

每个 action 内部都包裹了一层 `try-catch`，结构高度一致：

```
action(async () => {
  try {
    await commandImplementation(options);
    // 可能的 process.exit(0)
  } catch (err: any) {
    logError(err.message);
    process.exit(1);
  }
});
```

这一模式的作用是**将所有未捕获异常转化为统一的退出行为**：

1. `logError(err.message)` —— 使用 `chalk.red` 在控制台打印错误信息。详见 [日志与进度显示系统](日志与进度显示系统.md)。
2. `process.exit(1)` —— 以非零退出码终止进程，通知调用者失败。

由于 `action` 是异步函数，Commander.js 不会自动捕获其内部的 rejected promise。如果不手动包裹 try-catch，异常会被静默丢弃。这一屏障确保了**任何命令的错误都不会被静默吞噬**。

[来源](../src/cli.ts#L15-L56)

## 强制退出策略

三个命令的退出行为存在细微但关键的差异：

| 命令 | 成功时 | 失败时 | 原因 |
|------|--------|--------|------|
| `config` | 自然结束 | `process.exit(1)` | 没有长连接，inquirer 完成后进程自然退出 |
| `generate` | **`process.exit(0)`** | `process.exit(1)` | LLM 连接可能挂起，需要强制终止 |
| `browse` | 自然结束（HTTP 服务器保持运行） | `process.exit(1)` | 服务器需要保持监听，不能退出 |

**`generate` 的特殊性**：`generateCommand()` 内部会建立到 LLM API 的 HTTP 连接（经由 `LLMClient`）。如果 LLM 提供商使用流式响应（SSE），Node.js 的事件循环可能因未关闭的 socket 或 dangling 引用而无法自然退出。为此，`generate` 在成功完成后显式调用 `process.exit(0)` 来**强制终止进程**。

> 这是一个务实的取舍：在 CLI 工具中，强制退出带来的资源泄露风险远低于进程挂起带来的用户体验损失。

**`browse` 的反向逻辑**：`browseCommand()` 启动了一个 HTTP 服务器（[浏览生成的Wiki](浏览生成的Wiki.md)），需要事件循环保持活跃以处理请求。因此成功时不调用 `process.exit(0)`，让进程自然驻留。用户可通过 `Ctrl+C` 终止。

[来源](../src/cli.ts#L22-L56)

## 路由触发与默认帮助

```typescript
program.parse(process.argv);

if (!process.argv.slice(2).length) {
  program.outputHelp();
}
```

- `program.parse(process.argv)` 是 Commander.js 的路由触发器，解析命令行参数并执行匹配的 action。
- 如果用户没有传入任何子命令，则调用 `program.outputHelp()` 打印帮助文本。`parse` 本身不会在无参数时自动显示帮助（它只会在 `--help` 时输出），因此需要手动回退。

## 架构位置
