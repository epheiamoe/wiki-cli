# 文件系统工具集

在 Wiki 生成流程中，大量操作围绕 **文件读写** 与 **目录管理** 展开：创建临时目录、写入中间产物、移动最终结果、清理旧数据。`src/utils/file.ts` 将这些基础文件系统操作封装为 7 个导出函数，让上游调用方（主要是 `generate.ts`）不必关心跨平台路径分隔符、递归创建等底层细节。

## 总体架构

所有函数都是对 `node:fs/promises` 和 `node:path` 标准库的轻量封装，无第三方依赖。分为三类：

- **目录操作**：`ensureDir`、`removeDir`、`moveDir`
- **文件读写**：`fileExists`、`readTextFile`、`writeTextFile`
- **命名工具**：`getTimestamp`、`toSlug`

[来源](src/utils/file.ts#L1-L44)

## 目录操作

### `ensureDir(dirPath)` — 递归创建目录

其实现仅仅是一行：

```ts
await mkdir(dirPath, { recursive: true });
```

`recursive: true` 意味着无论 `dirPath` 的深度如何（如 `.wiki/temp` 或 `a/b/c`），都会完整创建整条路径，不会因父目录不存在而抛错。这是整个生成流程的起点 —— 在 [页面生成：逐页输出与并行加速](页面生成-逐页输出与并行加速.md) 阶段，`ensureDir(TEMP_DIR)` 确保 `.wiki/temp` 可用。

[来源](src/utils/file.ts#L5-L7)

### `removeDir(dirPath)` — 递归删除目录

```ts
if (existsSync(dirPath)) {
  await rm(dirPath, { recursive: true, force: true });
}
```

关键设计是 **先检查存在性，再调用 `rm`**。`force: true` 确保即便目录只读，删除也不会抛错。在 `generate.ts` 中，当用户选择"丢弃并重新生成"时，该方法用于清空之前的 `.wiki/temp`。

[来源](src/utils/file.ts#L18-L23)

### `moveDir(src, dest)` — 移动/重命名目录

直接映射 `rename` 系统调用：

```ts
await rename(src, dest);
```

在文件系统层面，`rename` 操作在同一个挂载点内是 **O(1) 的元数据操作**，不涉及数据拷贝。这是生成流程的收尾动作：将 `.wiki/temp` 通过 `moveDir(TEMP_DIR, finalDir)` 原子性地重命名为带时间戳的目录名。详见 [项目结构与模块职责](项目结构与模块职责.md) 中关于输出目录的描述。

[来源](src/utils/file.ts#L30-L32)

## 文件读写

### `fileExists(filePath)` — 文件存在性检查

```ts
return existsSync(filePath);
```

同步检查，用于快速判断中间产物是否存在，配合 [断点续传与失败重试](断点续传与失败重试.md) 机制跳过已生成的页面。

[来源](src/utils/file.ts#L9-L11)

### `readTextFile(filePath)` — 读取文本文件

```ts
return readFile(filePath, 'utf-8');
```

简单的 `fs.readFile` 封装，设置 `utf-8` 编码返回字符串。

[来源](src/utils/file.ts#L13-L15)

### `writeTextFile(filePath, content)` — 自动创建父目录后写入

这是 **生成流程中最核心的工具之一**，其实现值得细看：

```ts
await ensureDir(filePath.split(sep).slice(0, -1).join(sep));
await writeFile(filePath, content, 'utf-8');
```

它在写入前自动提取文件路径的 **父目录部分**，调用 `ensureDir` 确保目录已存在，然后再写入。这意味着调用方永远不需要手动创建目录 —— 只需指定目标路径即可。

在 `generate.ts` 中，该函数被用于三个关键场景：

| 场景 | 目标文件 | 用途 |
|------|----------|------|
| 保存大纲 | `.wiki/temp/_outline.json` | 供 [断点续传与失败重试](断点续传与失败重试.md) 使用 |
| 写入页面 | `.wiki/temp/{slug}.md` | 逐页输出 Markdown 内容 |
| 生成索引 | `.wiki/{timestamp}/index.json` | 输出最终的导航索引文件 |

[来源](src/utils/file.ts#L17-L21)

## 命名工具

### `getTimestamp()` — 生成文件系统安全的时戳

```ts
const now = new Date();
// ... 格式化为 "2025-03-20T14-30-05"
return `${y}-${M}-${d}T${h}-${m}-${s}`;
```

格式类似 ISO 8601，但将冒号（`:`）替换为连字符（`-`），因为在 Windows（FAT32/NTFS）和部分 Linux 文件系统中，冒号是非法字符。

生成的时戳用于 **最终输出目录命名**：`generate.ts` 在流程结束时用 `getTimestamp()` 得到 `"2025-03-20T14-30-05"`，然后将 `.wiki/temp` 重命名为 `.wiki/2025-03-20T14-30-05`。这样每次生成的 Wiki 都能保留独立的副本，便于回溯比较。

[来源](src/utils/file.ts#L34-L43)

### `toSlug(title)` — 中文友好的 Slug 生成

```ts
return title
  .toLowerCase()                       // 转为小写
  .replace(/[^\w\u4e00-\u9fff]+/g, '-') // 非单词/非中文字符 → -
  .replace(/^-+|-+$/g, '')             // 去掉首尾的 -
  || 'untitled';                       // 空输入回退
```

其正则表达式 `[^\w\u4e00-\u9fff]` 是设计核心 —— **保留了中文字符**（Unicode 范围 `\u4e00-\u9fff`），只将空格、标点、特殊符号替换为连字符。这意味着：

| 输入 | 输出 | 说明 |
|------|------|------|
| `概览` | `概览` | 纯中文原样保留 |
| `Quick Start Guide` | `quick-start-guide` | 英文标准 slug |
| `Hello 世界` | `hello-世界` | 中英文混合 |
| `测试@#文件!` | `测试-文件` | 特殊字符变为连字符 |

该函数在 `generate.ts` 的大纲解析阶段被调用 —— 每个 topic 的标题经过 `toSlug()` 处理后成为文件名。更多上下文参见 [大纲生成：代码理解与结构化输出](大纲生成-代码理解与结构化输出.md) 中的 slug 映射逻辑。

[来源](src/utils/file.ts#L45-L52)

## 在生成流程中的协作

下图展示这些工具在 `generate.ts` 中的完整生命周期：

```mermaid
flowchart LR
    A[开始生成] --> B[ensureDir TEMP_DIR]
    B --> C[大纲生成]
    C --> D[writeTextFile _outline.json]
    D --> E[页面生成]
    E --> F[toSlug→writeTextFile 每页.md]
    F --> G{moveDir .wiki/temp→.wiki/{timestamp}}
    G --> H[removeDir 清理旧数据]
    
    I[getTimestamp] --> G
```

每个阶段的文件操作职责：

1. **初始化**：`ensureDir('.wiki/temp')` 创建临时工作目录
2. **大纲持久化**：`writeTextFile` 将 LLM 返回的 JSON 大纲写入 `_outline.json`，供断点续传读取
3. **页面写入**：对每个 topic，先 `toSlug(title)` 生成文件名，再 `writeTextFile` 将 LLM 输出的 Markdown 写入对应 `.md` 文件
4. **收尾**：`getTimestamp()` 生成时间戳，`moveDir` 将 temp 目录原子性重命名为最终目录；如用户选择重新开始，`removeDir` 清空旧数据
