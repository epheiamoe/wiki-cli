# 日志与进度显示系统

想象一下，你运行命令后控制台一片漆黑，你不知道程序是在工作还是卡死了。`wiki-cli` 的日志与进度系统就是为了解决这个问题——它用颜色、图标和动画，让每一行输出都告诉你"现在发生了什么"。

所有的日志工具都集中在一个文件中，配合 **ora** 和 **chalk** 两个库，实现了一套简洁但完整的终端显示方案。[来源](../src/utils/progress.ts#L1-L2)

---

## 一目了然的六色日志

六个函数覆盖了程序运行中所有需要向用户传达的消息类型，每个都有专属的颜色和图标：

| 函数 | 颜色 | 图标 | 使用场景 |
|------|------|------|----------|
| `logInfo` | 蓝色 | ℹ | 流程提示，如"正在分析仓库结构" |
| `logSuccess` | 绿色 | ✔ | 操作成功，如"页面生成完成" |
| `logWarning` | 黄色 | ⚠ | 警告信息，如"跳过不支持的格式" |
| `logError` | 红色 | ✖ | 错误信息，如"API 请求失败" |
| `logToolCall` | 品红 | 🔧 | LLM 调用了某个工具，显示工具名+参数 |
| `logToolResult` | 绿色箭头 | ↳ | 工具调用的结果预览（截取前100字符） |

它们的实现极其简单——每个函数就是一行 `console.log`，配合 **chalk** 对文字着色：[来源](../src/utils/progress.ts#L8-L36)

```typescript
export function logInfo(msg: string): void {
  console.log(chalk.blue('ℹ'), msg);
}

export function logToolCall(name: string, args: any): void {
  console.log(chalk.magenta('🔧'), chalk.bold(`Tool: ${name}`), 
              chalk.gray(JSON.stringify(args)));
}

export function logToolResult(name: string, result: any): void {
  const preview = typeof result.data === 'string'
    ? result.data.slice(0, 100) + (result.data.length > 100 ? '...' : '')
    : JSON.stringify(result.data).slice(0, 100);
  console.log(chalk.green('  ↳'), chalk.gray(`Result: ${preview}`));
}
```

`logToolResult` 多了一个细节——它不会把完整结果全部打印出来，而是截取前100个字符再加省略号。这样既给了用户足够的反馈，又不会刷屏。[来源](../src/utils/progress.ts#L31-L36)

## 会转圈的进度指示器

长时间运行的任务需要一个"还在工作"的信号。`createSpinner` 是对 **ora** 库的一层薄封装：[来源](../src/utils/progress.ts#L4-L6)

```typescript
export function createSpinner(text: string) {
  return ora(text).start();
}
```

调用时传入一段文字，控制台就会显示一个旋转的动画光标（⠋、⠙、⠹……）。任务完成后，你可以调用 spinner 的 `.succeed()` 或 `.fail()` 方法，动画会定格为 ✔ 或 ✖ 图标。这套模式在 [页面生成：逐页输出与并行加速](页面生成-逐页输出与并行加速.md) 的处理流程中大量使用。

> **注意**：ora 在 v8 版本后已经是纯 ESM 包，只能被 `"type": "module"` 的项目 import。本项目已按此配置。[来源](../package.json#L10-L11)

## 流式逐字输出

在 **generate.ts** 中有一段特殊的输出方式——当 LLM 以流式（stream）模式返回内容时，程序不会等到全部数据到齐才显示，而是每收到一个 chunk 就立刻写入终端：[来源](../src/commands/generate.ts#L264-L273)

```typescript
// 推理过程（思考链）→ 淡黄色，带 "Thinking:" 前缀
process.stdout.write(chalk.dim.yellow('\nThinking: '));
process.stdout.write(chalk.dim.yellow(chunk.reasoning_content));

// 最终生成的文本 → 普通颜色
process.stdout.write(chunk.content ?? '');
```

这里使用 `process.stdout.write` 而不是 `console.log`，关键区别在于：**`console.log` 每次输出都会自动换行，而 `write` 不会**。逐字符流式效果正是靠这一点实现的——多个 chunk 的内容被连续写入同一行，让用户看到文字像打字机一样逐个出现。

这种体验在 [LLM客户端通信协议](llm客户端通信协议.md) 的流式模式中有更详细的说明。

## chalk v5：纯 ESM 的注意事项

项目中使用的 **chalk** 版本是 `^5.4.1`。从 v5 开始，chalk 变为纯 ESM 包，这意味着：

- 项目的 `package.json` 必须设定 `"type": "module"`
- 不能使用 `require('chalk')`，必须用 `import chalk from 'chalk'`
- 如果要在 CommonJS 项目中使用，需要降级到 chalk v4

本项目的 `tsconfig.json` 配置了 `"module": "ESNext"`，与 chalk v5 完全兼容。[来源](../tsconfig.json#L4)
