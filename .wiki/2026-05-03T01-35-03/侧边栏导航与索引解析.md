# 侧边栏导航与索引解析

> 本文是 [浏览生成的Wiki](浏览生成的wiki.md) 的技术深化篇，聚焦索引文件解析与前端交互实现细节。建议先阅读该文了解整体浏览流程。

---

## 数据模型：SidebarItem

侧边栏的原子数据结构是 **`SidebarItem`** 接口，定义了三字段：

```typescript
interface SidebarItem {
  title: string;   // 显示名称，如"安装与配置详解"
  slug: string;    // URL友好的标识符，如"安装与配置详解"
  level: string;   // 受众水平："初学"、"中级"、"高级"，或分组标记"group"
}
```

`level` 字段有双重作用：值为 `'group'` 时表示该条目是导航分组标题（不可点击），否则表示文档难度等级，用于前端渲染不同颜色的徽标。[来源](src/commands/browse.ts#L89-L93)

`slug` 由 **`slugify()`** 函数从 `title` 自动生成：转小写、非字母数字/中文替换为连字符、去掉首尾连字符。[来源](src/commands/browse.ts#L210-L212)

## 三层降级策略：loadSidebar

`loadSidebar` 函数采用**从精确到模糊的三层降级**策略，确保无论生成阶段留下何种索引格式，服务器都能正确构建导航。[来源](src/commands/browse.ts#L96-L118)

```mermaid
flowchart TD
    A[开始加载侧边栏] --> B{index.json 存在?}
    B -->|是| C[parseIndexJson]
    C --> D{解析成功?}
    D -->|是| E[返回 SidebarItem[]]
    D -->|否| F{index.md 存在?}
    B -->|否| F
    F -->|是| G[parseIndexXml]
    G --> H{解析成功?}
    H -->|是| E
    H -->|否| I[返回空数组]
    F -->|否| I
```

### 第一层：index.json（新格式）

`parseIndexJson` 解析生成阶段产出的 `index.json` 文件。处理流程：

1. **清理代码围栏**：调用 `stripCodeFence(content)` 移除可能的 Markdown 代码块包裹（兼容 LLM 生成时可能输出的围栏标记）
2. **JSON 提取**：用正则以 `/\{[\s\S]*\}/` 提取第一个 JSON 对象
3. **结构校验**：必须包含 `sections` 数组，每个 `section` 包含 `topics` 数组
4. **遍历 topics**：`type === 'group'` 的条目作为分组标题（`slug: ''`）；其余条目从 `topic.title` 自动生成 slug，`level` 默认 `'中级'`[来源](src/commands/browse.ts#L120-L151)

典型的 `index.json` 结构：

```json
{
  "sections": [
    {
      "sectionTitle": "入门",
      "topics": [
        { "type": "group", "title": "基础概念" },
        { "title": "快速开始", "level": "初学" },
        { "title": "安装与配置详解", "level": "中级" }
      ]
    }
  ]
}
```

### 第二层：index.md + XML 标签（旧格式）

`parseIndexXml` 处理旧版生成格式——在 `index.md` 文件中嵌入 XML 标签。解析规则：

- 用 `<section>` 和 `</section>` 界定有效范围（忽略外界内容）
- `<topic level="中级">标题</topic>` 提取页面条目
- `<group>标题</group>` 提取分组标题[来源](src/commands/browse.ts#L153-L177)

```xml
<section>
  <group>基础概念</group>
  <topic level="初学">快速开始</topic>
  <topic level="中级">安装与配置详解</topic>
</section>
```

### 第三层：扫描 .md 文件（当前为兜底占位）

代码注释为 `// Last resort: scan .md files`，但当前实现直接返回空数组 `[]`。这意味着如果前两层均失败，侧边栏将为空导航，首页 `firstContent` 也为空。[来源](src/commands/browse.ts#L116-L118)

> 这是一处有意未实现的占位——设计上预留了"扫描目录中所有 `.md` 文件自动构建导航"的扩展点，但目前生成阶段总会产出 `index.json` 或 `index.md`，因此实际运行中很少触发此分支。

## buildSidebarHtml：从数据到 DOM

`buildSidebarHtml` 将 `SidebarItem[]` 转换为有序的 `<li>` 列表 HTML：[来源](src/commands/browse.ts#L214-L222)

| item.level | 渲染方式 | 示例 |
|---|---|---|
| `'group'` | 无链接、大写字母间距的分组标题 | `<li class="nav-group">基础概念</li>` |
| `'初学'` | 🟢 绿色徽标 + 标题 | `<li><a href="#" onclick="loadPage('快速开始')">🟢 快速开始</a></li>` |
| `'中级'` | 🟡 黄色徽标 + 标题 | `<li><a href="#" onclick="loadPage('安装与配置详解')">🟡 安装与配置详解</a></li>` |
| `'高级'` | 🔴 红色徽标 + 标题 | `<li><a href="#" onclick="loadPage('命令行参考手册')">🔴 命令行参考手册</a></li>` |

每个可点击条目通过 `onclick` 直接调用全局函数 `loadPage(encodeURIComponent(item.slug))`。

## 前端 loadPage：异步页面加载

`serveHtml` 函数在服务器端渲染完整的 HTML 页面时，将以下 JavaScript 逻辑内联注入。[来源](src/commands/browse.ts#L248-L282)

```javascript
async function loadPage(encodedSlug) {
  const slug = decodeURIComponent(encodedSlug);
  const res = await fetch('/api/page/' + slug + '.md');
  const html = await res.text();
  document.getElementById('content').innerHTML = html;
  hljs.highlightAll();
  history.replaceState(null, '', '#' + slug);
}
```

执行四步操作：

1. **解码 slug**：`onclick` 传递的是 `encodeURIComponent` 编码后的值，需还原
2. **Fetch API**：请求 `/api/page/{slug}.md`，该路由在 [HTTP服务器与路由分发](http服务器与路由分发.md) 中有详细说明——服务器端读取对应 `.md` 文件，用 `marked` 解析为 HTML，并调用 `fixContentReferences` 将 `[来源：路径]` 标签替换为可点击的源码引用链接
3. **替换 DOM**：将 `#content` 容器的 innerHTML 设为返回的 HTML 片段
4. **代码高亮**：调用 `hljs.highlightAll()` 对新插入的代码块应用 Highlight.js
5. **更新 URL hash**：`history.replaceState(null, '', '#' + slug)` 将当前页面的 slug 写入 URL hash，不触发页面刷新

## URL Hash：直接定位到特定页面

页面加载时，`DOMContentLoaded` 事件处理器检查 `location.hash`：[来源](src/commands/browse.ts#L285-L291)

```javascript
if (location.hash) {
  const slug = decodeURIComponent(location.hash.slice(1));
  if (wikiSlugs.includes(slug)) {
    loadPage(slug);
  }
}
```

这意味着用户可以直接通过 `http://localhost:3000/#快速开始` 直达特定页面。`wikiSlugs` 数组在服务端渲染时由 `sidebarItems.filter(i => i.slug).map(i => i.slug)` 生成，作为 JavaScript 变量嵌入页面，用于校验 hash 值是否有效。

这个机制还支持浏览器的"前进/后退"导航——每次 `loadPage` 调用 `history.replaceState` 更新 hash，浏览器的历史记录会保留这些状态。

## 内部链接点击拦截

页面还注册了一个全局点击委托，拦截 `.md` 结尾的内部链接：[来源](src/commands/browse.ts#L293-L305)

```javascript
document.getElementById('content').addEventListener('click', function(e) {
  const anchor = e.target.closest('a');
  if (!anchor) return;
  const href = anchor.getAttribute('href');
  if (!href || href.startsWith('http') || href.startsWith('/api/') 
      || href.startsWith('#') || href.startsWith('mailto:')) return;
  e.preventDefault();
  if (href.endsWith('.md')) {
    loadPage(href.replace(/\.md$/, ''));
  } else {
    window.open('/api/source/' + href, '_blank');
  }
});
```

拦截规则：
- 外部链接（`http`）、API 链接（`/api/`）、锚点（`#`）、邮件链接放行
- `.md` 结尾的链接：调用 `loadPage` 做 SPA 式无刷新加载
- 其他链接（源码引用路径）：在新标签页打开 `/api/source/` 展示源码

## 数据流全景

```
生成阶段                    浏览阶段
─────────                 ─────────
index.json ──┬─→ loadSidebar ─→ parseIndexJson
              │                  ↓
index.md ─────┘         buildSidebarHtml
              │                  ↓
.md files ────┘          serveHtml(内联JS)
                               │
                    ┌──────────┴──────────┐
                    ↓                     ↓
            loadPage(slug)      URL hash 直达
                    │                     │
                    ↓                     ↓
           fetch /api/page/*.md   同一条 fetch 路径
                    │
                    ↓
          marked → HTML → DOM 更新
```
