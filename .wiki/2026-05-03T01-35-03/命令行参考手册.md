# 命令行参考手册

`wiki-cli` 暴露出三条顶级命令，分别对应配置、生成和浏览三个阶段。所有命令均由 **Commander.js** 驱动，注册与路由逻辑见 [命令调度与生命周期](命令调度与生命周期.md)。

## 全局行为

- 执行 `wiki-cli` 不带任何参数时，自动输出完整的 **帮助信息**（所有命令列表及用法概要）。
- 各命令失败时均通过 `process.exit(1)` 终止进程；生成命令成功时显式调用 `process.exit(0)` 表示正常结束。
- 退出码含义：

| 退出码 | 含义 |
|--------|------|
| `0`    | 成功 |
| `1`    | 失败（配置缺失、网络错误、生成异常等） |

## `wiki-cli config` — 交互式配置

配置 LLM 提供商、模型、API Key 和文档语言。支持两种模式：

### 模式一：静默模式（全参数传递）

如果同时传入了 `--provider`、`--base-url`、`--model`、`--api-key` 四个选项，则**跳过**交互式向导，直接保存配置并退出。详见 [配置持久化与模型注册表](配置持久化与模型注册表.md)。

### 模式二：交互式向导（默认）

缺省任何必选参数时，依次弹出选择菜单：
1. **选择 LLM 提供商**（7 个内置提供商 + 自定义选项）
2. **选择模型**（按提供商过滤的内置模型列表，含定价提示）
3. **输入 API Key**（密码掩码输入）
4. **确认 JSON mode**（内置已知列表自动判断，未知则询问用户）
5. **输入文档语言**（`zh` 或 `en`，默认 `zh`）

### 选项一览

| 选项 | 类型 | 默认值 | 必填 | 说明 |
|------|------|--------|------|------|
| `--provider <provider>` | `string` | 交互式选择 | 否 | LLM 提供商名称，如 `"OpenAI"` |
| `--base-url <url>` | `string` | 交互式输入 | 否 | API 基础 URL |
| `--model <model>` | `string` | 交互式选择 | 否 | 模型名称 |
| `--api-key <key>` | `string` | 交互式输入 | 否 | API 密钥 |
| `--lang <lang>` | `"zh"` \| `"en"` | `"zh"` | 否 | 文档语言 |

## `wiki-cli generate` — 生成 Wiki 文档

分析当前工作目录的代码仓库，分两阶段生成 Wiki 页面。

### 子流程

1. **检测临时目录**：若存在 `.wiki/temp`，询问「续传」还是「重新开始」；详见 [断点续传与失败重试](断点续传与失败重试.md)。
2. **阶段一：生成大纲**（Outline）— LLM 通过工具调用探索仓库，输出 JSON 格式大纲。支持最多 25 轮对话与 JSON 解析回退。
3. **询问并行方式**：选择串行（流式输出，逐页可见）或并行（并发加速，无流式），并发数 1–10，默认 3。
4. **阶段二：逐页生成**（Pages）— 基于大纲生成 Markdown 文件，支持失败重试循环。
5. **收尾**：将临时目录移动到带时间戳的 `.wiki/YYYYMMDD-HHmmss` 目录，并生成 `index.json` 索引文件。

### 选项一览

`generate` 命令本身**不接收任何命令行选项**。所有参数（并行模式、并发数、续传/重试决策）均在运行时通过 **inquirer** 交互式提示完成。

| 选项 | 类型 | 默认值 | 必填 | 说明 |
|------|------|--------|------|------|
| （无） | — | — | — | 全部通过交互式提示完成 |

## `wiki-cli browse` — 浏览生成的 Wiki

启动本地 HTTP 服务器，自动在默认浏览器中打开生成的 Wiki 页面。

### 行为

1. 扫描 `.wiki/` 目录下的所有时间戳子目录，选取**最新的**一个。
2. 读取 `index.json`（或回退到 `index.md` XML 格式）构建侧边栏导航。
3. 在第一个可用端口（从 `3000` 开始递增查找空闲端口）启动 HTTP 服务器。
4. 自动调用系统命令打开浏览器（`start` / `open` / `xdg-open` 根据平台自动选择）。
5. 服务器内置三条 API 路由：
   - `/api/page/{slug}.md` — 返回渲染后的 HTML
   - `/api/source/{path}` — 返回源文件代码（带语法高亮）
   - `.md` 结尾请求自动 302 重定向至 `/api/page/`

详见 [浏览生成的 Wiki](浏览生成的wiki.md) 和 [HTTP服务器与路由分发](http服务器与路由分发.md)。

### 选项一览

`browse` 命令**不接收任何命令行选项**。

| 选项 | 类型 | 默认值 | 必填 | 说明 |
|------|------|--------|------|------|
| （无） | — | — | — | 自动选择最新 Wiki、查找可用端口 |

## 用例组合

### 示例 1：首次配置 + 生成 + 浏览（完整链路）

```bash
# 静默配置（快速设定）
wiki-cli config --provider OpenAI --base-url https://api.openai.com/v1 \
  --model gpt-5.4-nano --api-key sk-xxxxx --lang zh

# 生成 Wiki（交互式：选择并行模式）
wiki-cli generate

# 打开浏览器浏览
wiki-cli browse
```

### 示例 2：仅交互式配置 + 串行生成（调试用）

```bash
# 仅传入语言，其余全部交互式选择
wiki-cli config --lang en

# 串行生成（选「否」跳过并行），可观察每页的流式输出
wiki-cli generate

# 浏览最新生成的 Wiki
wiki-cli browse
```

### 示例 3：断点续传（中断后恢复）

```bash
# 第一次生成中途 Ctrl+C 中断
wiki-cli generate

# 再次运行，选择「续传」选项
wiki-cli generate
# → 提示 "Resume from last checkpoint"
# → 跳过已生成的页面，只生成剩余页面
```

关于断点续传的详细原理，参见 [断点续传与失败重试](断点续传与失败重试.md)。

## 退出码汇总

| 场景 | 退出码 | 说明 |
|------|--------|------|
| 正常完成 `generate` | `0` | 显式调用 `process.exit(0)` |
| 配置缺失导致 `generate` 无法运行 | `1` | 提示 "No configuration found" |
| 大纲生成失败（无 topics） | `1` | 提示 "Failed to generate outline" |
| `config` 命令异常 | `1` | 任何抛出的错误 |
| `browse` 无 `.wiki` 目录 | `1` | 提示 "No .wiki directory found" |
| `browse` 无生成的 Wiki | `1` | 提示 "No generated Wiki found" |
