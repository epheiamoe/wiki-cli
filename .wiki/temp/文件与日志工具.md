# 文件与日志工具

wiki-cli 项目将底层操作抽象为两个职责清晰的工具模块：`src/utils/file.ts` 专攻跨平台文件系统操作，`src/utils/progress.ts` 专攻终端用户界面的日志输出。两者组合为上层命令（[生成 Wiki](生成-wiki.md)、[AI 问答](ai-问答.md)、[浏览 Wiki](浏览-wiki.md)）提供了可复用的基础设施。

---

## 文件操作：`file.ts`

文件模块封装了 Node.js `fs/promises` 的异步 API，所有函数均返回 `Promise`，适合在 async 流程中直接 `await`。

### 核心三件套：读、写、确保目录

`readTextFile` 和 `writeTextFile` 是最频繁使用的一对函数：

```ts
// file.ts#L10-L11 — 读文件
export async function readTextFile(filePath: string): Promise<string> {
  return readFile(filePath, 'utf-8');
}

// file.ts#L14-L17 — 写文件，自动创建父目录
export async function writeTextFile(filePath: string, content: string): Promise<void> {
  await ensureDir(filePath.split(sep).slice(0, -1).join(sep));
  await writeFile(filePath, content, 'utf-8');
}
```

`writeTextFile` 在写入前自动提取路径中的目录部分并调用 `ensureDir`，调用方无需额外准备目录结构。[来源](src/utils/file.ts#L10-L17)

`ensureDir` 本身是对 `mkdir` `{ recursive: true }` 的直接包装，幂等可用。[来源](src/utils/file.ts#L4-L6)

### 跨设备目录移动：`moveDir` 的 fallback 策略

`moveDir` 是文件模块中最具设计巧思的函数。它先尝试 `rename`——原生的文件系统重命名操作，在 **同一文件系统内** 是原子的、零拷贝的。但一旦源和目标位于不同设备（如从 `/tmp` 移到 `/home`），操作系统会抛出 `EXDEV`（跨设备链接错误）。

```ts
// file.ts#L32-L43
export async function moveDir(src: string, dest: string): Promise<void> {
  try {
    await rename(src, dest);
  } catch (err: any) {
    if (err.code === 'EXDEV') {
      await cp(src, dest, { recursive: true });
      await rm(src, { recursive: true, force: true });
    } else {
      throw err;
    }
  }
}
```

fallback 流程：

1. 尝试 **rename** — O(1)，仅修改目录项指针
2. `EXDEV` 捕获后，执行 **cp + rm** — O(n)，逐文件拷贝后删除源目录
3. 其他错误直接抛出，不静默吞掉

在 `generate.ts` 中，临时构建的 Wiki 目录（`TEMP_DIR`）通过 `moveDir` 移到带有时间戳的最终目录 `wiki-{timestamp}`，这正是该 fallback 发挥作用的关键场景。[来源](src/utils/file.ts#L32-L43)

### 时间戳：`getTimestamp`

`getTimestamp` 生成适合作为目录名的 ISO 风格时间字符串：

```ts
// file.ts#L45-L54
export function getTimestamp(): string {
  const now = new Date();
  const y = now.getFullYear();
  const M = String(now.getMonth() + 1).padStart(2, '0');
  const d = String(now.getDate()).padStart(2, '0');
  const h = String(now.getHours()).padStart(2, '0');
  const m = String(now.getMinutes()).padStart(2, '0');
  const s = String(now.getSeconds()).padStart(2, '0');
  return `${y}-${M}-${d}T${h}-${m}-${s}`;
}
```

输出格式：`2025-04-13T14-32-05`

与传统 ISO 8601 `2025-04-13T14:32:05` 的区别在于用连字符 `-` 取代了冒号 `:`，这是有意为之——冒号在 Windows 和部分 Unix 文件系统中属于非法字符，无法直接作为目录名。生成 Wiki 时产生的版本目录就是以此命名，例如 `wiki-2025-04-13T14-32-05`。[来源](src/utils/file.ts#L45-L54)

### 中文友好的 Slugify：`toSlug`

```ts
// file.ts#L56-L60
export function toSlug(title: string): string {
  return title
    .toLowerCase()
    .replace(/[^\w\u4e00-\u9fff]+/g, '-')
    .replace(/^-+|-+$/g, '')
    || 'untitled';
}
```

标准的 slugify 做法是用 `\w`（`[a-zA-Z0-9_]`）保留字母数字，但这里增加了 `\u4e00-\u9fff` 范围——覆盖了 **常用汉字（CJK Unified Ideographs）**。这意味着 "文件与日志工具" 会被 slug 化为 `文件与日志工具` 而非被剥离成空字符串。

处理步骤：

| 步骤 | 转换 | 示例 |
|------|------|------|
| 小写 | `toLowerCase()` | `"Hello 世界"` → `"hello 世界"` |
| 连续非保留字符替换 | `replace` → `-` | `"hello 世界"` → `"hello-世界"` |
| 首尾连字符修剪 | `trim` → `^-\|-$` | `"-hello-"` → `"hello"` |
| 空值兜底 | `\|\| 'untitled'` | `""` → `"untitled"` |

该函数在[两阶段生成引擎](两阶段生成引擎.md)中被广泛调用，用于将 LLM 输出的页面标题转为文件名 slug。[来源](src/utils/file.ts#L56-L60)

## 日志与进度：`progress.ts`

`progress.ts` 是项目的用户界面层，控制终端中的每一条输出。它依赖两个经典 NPM 库：`chalk`（着色）和 `ora`（旋转动画）。

### 四色日志体系

四个基本日志函数定义了统一的视觉语言：

| 函数 | 前缀图标 | Chalk 颜色 | 语义 |
|------|----------|------------|------|
| `logInfo` | `ℹ` | `blue` | 通知性信息 |
| `logSuccess` | `✔` | `green` | 操作成功完成 |
| `logWarning` | `⚠` | `yellow` | 非致命异常，需关注 |
| `logError` | `✖` | `red` | 操作失败/异常中断 |

```ts
// progress.ts#L8-L23
export function logInfo(msg: string): void {
  console.log(chalk.blue('ℹ'), msg);
}
export function logSuccess(msg: string): void {
  console.log(chalk.green('✔'), msg);
}
export function logWarning(msg: string): void {
  console.log(chalk.yellow('⚠'), msg);
}
export function logError(msg: string): void {
  console.log(chalk.red('✖'), msg);
}
```

所有函数使用 `console.log` + 前缀图标 + `chalk` 着色，而非 `console.error` 或 `process.stderr`，确保输出顺序与 stdout 流一致。[来源](src/utils/progress.ts#L8-L23)

在代码库中的调用分布：

| 命令 | 主要使用场景 |
|------|-------------|
| [生成 Wiki](生成-wiki.md) | 阶段切换通知、页面生成成功/失败、增量更新回退警告 |
| [AI 问答](ai-问答.md) | 会话创建/切换/删除、API 错误、最大迭代次数警告 |
| [浏览 Wiki](浏览-wiki.md) | 启动服务器、目录状态检查 |
| [查看状态](查看状态.md) | 版本查询、差异提示 |

### 流式内容输出

`logStreamContent` 专为 LLM 流式响应设计，使用 `process.stdout.write` 而非 `console.log`，避免自动追加换行符：

```ts
// progress.ts#L25-L26
export function logStreamContent(content: string): void {
  process.stdout.write(chalk.cyan(content));
}
```

这使得 AI 输出的 token 可以连续显示在同一行，逐块拼装成完整句子。在 `generate.ts` 和 `ai.ts` 的流式循环中调用。[来源](src/utils/progress.ts#L25-L26)

### 工具调用日志

`logToolCall` 和 `logToolResult` 专为 Tool-augmented 循环设计，在[两阶段生成引擎](两阶段生成引擎.md)和[AI 问答](ai-问答.md)中都有使用：

```ts
// progress.ts#L28-L36
export function logToolCall(name: string, args: any): void {
  console.log(chalk.magenta('🔧'), chalk.bold(`Tool: ${name}`), chalk.gray(JSON.stringify(args)));
}

export function logToolResult(name: string, result: any): void {
  const preview = typeof result.data === 'string'
    ? result.data.slice(0, 100) + (result.data.length > 100 ? '...' : '')
    : JSON.stringify(result.data).slice(0, 100);
  console.log(chalk.green('  ↳'), chalk.gray(`Result: ${preview}`));
}
```

调用时以洋红色打印工具名称与参数，结果则缩进一行以绿色箭头引导、灰色显示前 100 字符的预览。这种缩进编排帮助用户在终端中直观区分"谁调用了谁"的调用链。[来源](src/utils/progress.ts#L28-L36)

### Spinner 动画

`createSpinner` 是对 `ora` 库的一行包装：

```ts
export function createSpinner(text: string) {
  return ora(text).start();
}
```

返回的 `ora.Ora` 实例支持 `.succeed(text)`、`.fail(text)`、`.stop()` 等方法，用于表示耗时操作的中间状态（如 LLM 请求等待）。[来源](src/utils/progress.ts#L4-L6)

## 设计观察

两个模块遵循共同的设计原则：**保持简单，只封装一次**。`file.ts` 的函数只做一件事——`writeTextFile` 顺带创建目录是因为每次写入几乎都需要它，属于合理的正交合并；`moveDir` 的 EXDEV fallback 是对 Node.js 跨设备限制的透明补偿。`progress.ts` 的函数更薄——没有日志级别、没有配置文件、没有格式化选项，但输出模式在代码中全局一致，无需额外配置即可获得可读性。

如果你需要为 wiki-cli 贡献新命令，这两个文件是你最先要查阅的底层库。完整的函数签名概览也已通过[工具调用](工具调用.md)的 `get_file_tools` 暴露给外部 Agent。
