# 文件系统实用工具

`src/utils/file.ts` 是一个薄薄的工具层——总共不到 60 行代码，却承担了整个 wiki-cli 全部的文件 IO 操作。从创建临时目录、写入生成的页面、移动最终产物到清理缓存，所有涉及磁盘的行为最终都落在这个模块上。

本文从源码出发，逐一拆解 7 个工具函数的设计意图与实现细节。

---

## 目录操作三件套

### `ensureDir` —— 递归安全创建

```typescript
export async function ensureDir(dirPath: string): Promise<void> {
  await mkdir(dirPath, { recursive: true });
}
```

这是整个模块的基石。它直接将 `node:fs/promises` 的 `mkdir` 包裹一层，传入 `{ recursive: true }` 后，无论目标路径的父目录是否存在，都会一路创建到底。如果目录已存在，它也不会报错——幂等性保证了调用方无需前置检查。

在 [生成命令详解](生成命令详解.md) 的流程中，`ensureDir` 被用于创建临时工作目录 `TEMP_DIR`，确保后续所有文件写入都有宿主可依。[来源](src/utils/file.ts#L5-L7)

### `removeDir` —— 递归清扫

```typescript
export async function removeDir(dirPath: string): Promise<void> {
  if (existsSync(dirPath)) {
    await rm(dirPath, { recursive: true, force: true });
  }
}
```

对称的反操作。`rm` 的 `recursive: true` 允许删除非空目录，`force: true` 让它在文件不存在时也不抛异常。外层再加一层 `existsSync` 检查，相当于双重保险——即便目录已被其他逻辑删除，调用 `removeDir` 也不会中断流程。

在生成命令的 "fresh" 模式下，它被用于清除上一次生成的临时目录，腾出空间重新创建。[来源](src/utils/file.ts#L22-L27)

### `moveDir` —— 原子重命名

```typescript
export async function moveDir(src: string, dest: string): Promise<void> {
  await rename(src, dest);
}
```

直接代理到 `rename` 系统调用。在同一个文件系统内，`rename` 是原子的——目标路径不存在时直接重命名，存在时则覆盖。生成流程的最终阶段，临时目录 `TEMP_DIR` 通过 `moveDir` 一次性变为带时间戳的最终目录，全程无文件拷贝开销。[来源](src/utils/file.ts#L32-L34)

## 文件读写与路径推导

### `writeTextFile` —— 自动补位写入

```typescript
export async function writeTextFile(filePath: string, content: string): Promise<void> {
  await ensureDir(filePath.split(sep).slice(0, -1).join(sep));
  await writeFile(filePath, content, 'utf-8');
}
```

这个函数的核心设计意图是：**调用方无需关心目录是否存在**。

关键逻辑在第二行的路径分割：

```
filePath.split(sep).slice(0, -1).join(sep)
```

以 Windows 的 `\\` 分隔符为例，如果传入 `C:\\output\\wiki\\hello.md`：
- `split(sep)` → `['C:', 'output', 'wiki', 'hello.md']`
- `slice(0, -1)` → `['C:', 'output', 'wiki']`
- `join(sep)` → `C:\\output\\wiki`

这就从文件路径中提取出了父目录路径，交给 `ensureDir` 创建。无论路径嵌套多深，写入前父目录必然就位。

在 [两阶段生成：大纲与页面](两阶段生成：大纲与页面.md) 中，`writeTextFile` 被用来写入三个不同的目标：`_outline.json` 大纲缓存、每个页面的 Markdown 文件、以及最终的 `index.json` 导航索引。[来源](src/utils/file.ts#L17-L20)

### `listDir` / `fileExists` / `readTextFile`

这三个是标准 `fs/promises` 的一对一封装：

| 函数 | 底层调用 | 作用 |
|------|----------|------|
| `listDir` | `readdir` | 读取目录下所有条目名 |
| `fileExists` | `existsSync` | 同步检查文件是否存在 |
| `readTextFile` | `readFile` + `utf-8` | 以 UTF-8 读取文本文件 |

它们的存在保持了一致性——项目内所有文件操作都可以从 `../utils/file.js` 导入，而非散落在各处引用原生 fs。[来源](src/utils/file.ts#L9-L15)

## 辅助格式化

### `getTimestamp` —— 安全的本地时间戳

```typescript
export function getTimestamp(): string {
  const now = new Date();
  const y = now.getFullYear();
  const M = String(now.getMonth() + 1).padStart(2, '0');
  const d = String(now.getDate()).padStart(2, '0');
  const h = String(now.getHours()).padStart(2, '0');
  const m = String(now.getMinutes()).padStart(2, '0');
  const s = String(now.getSeconds()).padStart(2, '0');
  return `${y}-${M}-${d}T${h}-${m}-${s}`;
}
```

格式为 `YYYY-MM-DDTHH-mm-ss`，注意时间分隔符用的是 `-` 而非标准 ISO 中的 `:`——这是为了跨平台文件名兼容（Windows 文件名不允许 `:`）。返回值适合直接拼入目录或文件名。

在生成流程的收尾阶段，`getTimestamp()` 生成的字符串被拼接为最终 Wiki 目录的名称（如 `wiki-2026-03-16T14-30-05`），使其按时间自然排序。[来源](src/utils/file.ts#L36-L45)

### `toSlug` —— 中文兼容的 URL Slug

```typescript
export function toSlug(title: string): string {
  return title
    .toLowerCase()
    .replace(/[^\w\u4e00-\u9fff]+/g, '-')
    .replace(/^-+|-+$/g, '')
    || 'untitled';
}
```

三步变换：

1. **全小写** — 标准化英文字母大小写。
2. **非单词字符替换** — 正则 `[^\w\u4e00-\u9fff]` 匹配所有非字母数字下划线且非中文字符的片段，替换为单个 `-`。`\u4e00-\u9fff` 覆盖了中日韩统一表意文字（CJK Unified Ideographs），这是 Unicode 中基本中文汉字区段，确保中文标题不会被全部抹除。
3. **修剪首尾连字符** — `^-+|-+$` 去除两端多余的 `-`。

如果结果为空字符串（例如标题全是特殊符号），兜底返回 `'untitled'`。

在 [两阶段生成：大纲与页面](两阶段生成：大纲与页面.md) 的 Phase 1 中，每个页面标题都会经过 `toSlug` 转成文件名标识，作为 `{ slug, title }` 对写入大纲 JSON。这保证了中文标题的 Wiki 页面拥有可读且合法的文件名。[来源](src/utils/file.ts#L47-L54)

## 这些工具如何串联

从完整的生成流程中可以直观看到 7 个函数的协作顺序：

```
removeDir(TEMP_DIR)       ← 清理旧临时目录
    ↓
ensureDir(TEMP_DIR)       ← 创建新临时目录
    ↓
writeTextFile(大纲)       ← 写入 _outline.json
writeTextFile(页面)       ← 逐页写入 Markdown
writeTextFile(index.json) ← 写入导航索引
    ↓
moveDir(TEMP_DIR → final) ← 原子重命名为最终目录
    ↓
toSlug(title)             ← 每页标题转文件名
getTimestamp()            ← 最终目录的时间戳名
```

这一设计链条在 [项目架构全景](项目架构全景.md) 中属于 **工具层** 的一部分，与 [工作目录解析与远程仓库](工作目录解析与远程仓库.md) 中的 `resolveWorkDir` 共用同一 `utils` 目录。
