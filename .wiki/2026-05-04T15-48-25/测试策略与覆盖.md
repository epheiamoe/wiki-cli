# 测试策略与覆盖

项目采用 **Vitest** 作为测试框架，共 **71 个测试用例**，分布在 6 个测试文件中。测试策略围绕三个核心设计边界展开：**错误路径**（网络异常、API 错误、无效输入）、**边界输入**（空值、特殊字符、极端长度）、**正常路径**（核心功能验证）。所有测试文件使用 `*.test.ts` 命名约定，位于 `tests/` 目录。

## 测试配置

`vitest.config.ts` 使用 `defineConfig` 定义三项全局配置：

```ts
export default defineConfig({
  test: {
    globals: true,          // 全局注入 describe/it/expect
    environment: 'node',    // Node 运行环境
    include: ['tests/**/*.test.ts'], // 测试文件匹配模式
  },
});
```

- `globals: true` 允许在测试文件中直接使用 `describe`、`it`、`expect` 等 API 而无需从 `vitest` 导入（但现行测试文件仍显式导入了这些函数）。
- `environment: 'node'` 确保测试运行在 Node.js 环境而非浏览器 DOM 环境。
- `include` 模式限定只匹配 `tests/` 目录下的 `.test.ts` 文件。

### llm-client.test.ts — LLM 客户端通信

核心亮点是对网络层的 **mock 策略**：通过 `vi.fn().mockResolvedValue` 替代 `globalThis.fetch`，模拟服务端返回的各种 SSE 数据流。不发起真实网络请求。

**流式通信 (chatStream)：**
- 模拟多个 `data:` 分块，验证 `content` 类型块被逐个 yield
- 模拟 `tool_calls` 增量块，验证 `tool_call` 类型块的触发
- 模拟 `reasoning_content` 块（DeepSeek 等推理模型），验证拼接行为
- 模拟 HTTP 401 错误，验证 `error` 类型块的处理
- 使用 `createMockStream` 工具函数构造分块流，包含终止标志 `data: [DONE]`

**非流式通信 (chat)：**
- 验证请求体的 `model`、`messages`、`tools` 字段格式正确
- 验证 `reasoning_content` 回传逻辑：assistant 消息携带 `reasoning_content` 字段时，序列化后能正确传递

**重试策略：**
- 5xx 错误（502/503）自动重试，最多 3 次
- 网络异常（如 `ECONNRESET`）自动重试，测试验证 2 次失败后第 3 次成功
- 4xx 错误（401）**不重试**，立即返回错误
- 流式 + 非流式双通道均覆盖重试逻辑

**边界校验：**
- `baseUrl` 拼接为 `${baseUrl}/chat/completions` 格式

[来源](tests/llm-client.test.ts#L1-L214)

## 测试设计边界

项目测试围绕三条设计边界构建：

### 错误路径覆盖

测试不仅验证"应该成功"的场景，更验证"失败时行为正确"：

- HTTP 401 → 不重试，即时报错
- HTTP 502/503 → 自动重试，指数退避（1s、2s、4s）
- 网络异常（ECONNRESET）→ 重试并最终成功
- 文件不存在 → 返回结构化 error 结果
- 必填参数缺失 → 错误信息明确指示缺失字段
- 无效 JSON → 返回空数组而非崩溃

### 边界输入覆盖

- 空字符串（Slug、模板变量、大纲解析）
- 特殊字符（Slug 中的 `@#$!`）
- 连续分隔符（Slug 中的多个空格和连字符）
- 未提供变量（模板占位符原样保留）
- 代码围栏包裹/附加文本（从噪声中提取 JSON）

### 网络异常覆盖

`llm-client.test.ts` 通过 mock 覆盖：

- **瞬态服务端错误**（5xx）：自动重试直至成功
- **客户端错误**（4xx）：不重试、快速失败
- **底层网络异常**（`ECONNRESET`）：重试直至耗尽配额
- **超时场景**：`fetch_web_markdown` 内置 15 秒 AbortController 超时
