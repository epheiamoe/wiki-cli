# 侧栏导航与版本管理

`browseCommand` 启动 HTTP 服务器后，第一个 HTTP 请求到达根路径 `/` 时，会触发侧栏导航树的构建和首页渲染。整个过程分为三步：读取 `index.json`、解析为扁平的 `SidebarItem[]` 列表、再渲染为带层次感的 HTML 列表。与此同时，版本管理子系统在同一次页面请求中完成版本列表的加载、排序和 overlay UI 的注入。

---

## index.json 的三层结构

`index.json` 由 [生成命令：wiki-cli generate](生成命令-wiki-cli-generate.md) 的 `generateIndex` 函数写入，其 JSON 结构遵循严格的嵌套模式：

```json
{
  "sections": [
    {
      "name": "入门指南",
      "topics": [
        { "type": "group", "title": "基础知识" },
        { "level": "初学", "title": "概览" }
      ]
    }
  ]
}
```

三层结构为：**sections → topics → topic**。每个 section 包含一个 topics 数组；每个 topic 要么是普通页面条目（含 `level` 和 `title`），要么是类型为 `group` 的分组标题。[来源](src/commands/generate.ts#L596-L616)

`sections` 数组的去重逻辑基于 `Set`：`[...new Set(topics.map(t => t.section).filter(Boolean))]`，这意味着大纲中同一 section 名的所有 topic 会被归并到同一个 section 下。section 的**顺序**由 `Set` 的插入顺序决定，即 topics 数组中首次出现的 section 顺序。[来源](src/commands/generate.ts#L594)

## loadSidebar：解析入口

`loadSidebar` 函数尝试两种文件格式，优先级为 `index.json` > `index.md`：

```ts
async function loadSidebar(wikiPath: string): Promise<SidebarItem[]> {
  const jsonPath = join(wikiPath, 'index.json');
  if (existsSync(jsonPath)) {
    const content = await readFile(jsonPath, 'utf-8');
    return parseIndexJson(content);
  }
  // fallback: index.md XML-like format
  const mdPath = join(wikiPath, 'index.md');
  if (existsSync(mdPath)) {
    const content = await readFile(mdPath, 'utf-8');
    return parseIndexXml(content);
  }
  return [];
}
```

`index.md` 回退格式是一种类 XML 的标记，用于兼容早期版本的生成输出。当前主流路径始终是 `index.json`。[来源](src/commands/browse.ts#L258-L275)

## parseIndexJson：sections→topics 到 SidebarItem[] 的映射

`parseIndexJson` 是整个侧栏导航的**数据转换层**。它接收 `index.json` 的原始 JSON 字符串，输出扁平的 `SidebarItem[]`：

```ts
interface SidebarItem {
  title: string;
  slug: string;
  level: string;
}
```

转换逻辑的核心循环：

```ts
for (const section of parsed.sections) {
  if (!section.topics || !Array.isArray(section.topics)) continue;
  for (const topic of section.topics) {
    if (topic.type === 'group') {
      items.push({ title: topic.title, slug: '', level: 'group' });
    } else if (topic.title) {
      items.push({ title: topic.title, slug: slugify(topic.title), level: topic.level || '中级' });
    }
  }
}
```

关键设计决策：

1. **section 层被扁平化** — 原始的 `sections` 数组结构在输出中被抹平，section 名称本身**不会**出现在 `SidebarItem[]` 中。这意味着 section 仅作为生成时的组织单元，不直接影响 UI 的视觉分组。视觉分组完全由 `type: 'group'` 的 topic 条目控制。
2. **group 类型条目** — 当 `topic.type === 'group'` 时，生成一个 `slug: ''`、`level: 'group'` 的条目。空 slug 意味着它不是一个可点击的页面链接，而是灰色分组标题。
3. **普通条目** — 不包含 `type` 字段（或 `type` 非 `group`）且有 `title` 的 topic，通过 `slugify(topic.title)` 生成页面 slug，`level` 从 `topic.level` 直接复制，兜底值为 `'中级'`。
4. **JSON 清理** — 调用 `stripCodeFence` 去除可能的 Markdown 代码围栏，再用正则 `/\{[\s\S]*\}/` 提取最外层 JSON 对象。[来源](src/commands/browse.ts#L284-L306)

## buildSidebarHtml：group 渲染为灰色分组标题

`buildSidebarHtml` 将 `SidebarItem[]` 转为 `<li>` 列表的 HTML 字符串，核心是两种渲染路径的分支：

```ts
function buildSidebarHtml(items: SidebarItem[]): string {
  const parts = items.map(item => {
    if (item.level === 'group')
      return `<li class="nav-group">${item.title}</li>`;
    const badge = item.level === '初学' ? '🟢'
      : item.level === '中级' ? '🟡' : '🔴';
    return `<li><a href="#" onclick="loadPage('${encodeURIComponent(item.slug)}')">${badge} ${item.title}</a></li>`;
  });
  return parts.join('\n');
}
```

- **group 条目** — 渲染为 `<li class="nav-group">`，CSS 中对应 `color: #484f58; font-size: 11px; text-transform: uppercase; letter-spacing: 1px;` — 灰色小号大写字母，作为分组标题，不可点击。
- **普通条目** — 渲染为带难度徽标的可点击 `<a>` 标签。三个难度级别对应三色圆点：初学 🟢（绿色）、中级 🟡（黄色）、高级 🔴（红色）。徽标通过 HTML 实体直接嵌入，无需 CSS 额外处理。
- **slug 编码** — `encodeURIComponent(item.slug)` 确保中文或特殊字符的 slug 能被安全嵌入 `onclick` 属性。[来源](src/commands/browse.ts#L340-L350)

生成的 HTML 被注入到 `serveHtml` 中的模板字符串中，位于 `<ul>${sidebarHtml}</ul>` 位置。[来源](src/commands/browse.ts#L382)

## slugify 函数

`browse.ts` 内部定义了独立的 `slugify` 函数，与 `src/utils/file.ts` 中的 `toSlug` 函数逻辑完全一致：

```ts
function slugify(title: string): string {
  return title.toLowerCase()
    .replace(/[^\w\u4e00-\u9fff]+/g, '-')
    .replace(/^-+|-+$/g, '') || 'untitled';
}
```

三步处理：全小写 → 非字母数字汉字字符替换为连字符 → 去除首尾连字符。`\u4e00-\u9fff` 覆盖了所有 CJK 统一汉字，确保中文原样保留。[来源](src/commands/browse.ts#L334-L338)

这个函数与 `src/utils/file.ts` 导出的 `toSlug` 是**重复定义**——browse 命令没有引用 file 模块，而是复制了一份相同的逻辑。`[文件系统实用工具](文件系统实用工具.md)` 中详细分析了 `toSlug` 的行为。[来源](src/commands/browse.ts#L1-L4)[来源](src/utils/file.ts#L44-L50)

## 版本列表的排序逻辑

版本列表在 `browseCommand` 启动时通过文件系统扫描生成：

```ts
const entries = await readdir(wikiDir, { withFileTypes: true });
const timestamps = entries
  .filter(e => e.isDirectory() && e.name !== 'temp' && e.name !== 'sessions')
  .map(e => e.name)
  .sort()
  .reverse();
```

三步处理：

1. **筛选目录** — 只保留是目录的条目，排除 `temp`（生成中的临时目录）和 `sessions`（AI 问答会话存储目录）
2. **提取名称** — 目录名即为时间戳字符串，格式如 `2024-01-15T14-30-00`
3. **排序反转** — `Array.prototype.sort()` 默认按字符串字典序升序排列，然后 `.reverse()` 转为降序。**最新版本在最前面**（`timestamps[0]`），这是由 `getTimestamp` 的 ISO-like 格式保证的——年-月-日T时-分-秒的字符串排序天然等同于时间先后排序。[来源](src/commands/browse.ts#L37-L43)

版本列表同时还通过 `/api/versions` JSON 端点暴露：

```ts
if (pathname === '/api/versions') {
  const list = allVersions.map(v => ({
    ts: v,
    current: v === version,
  }));
  res.writeHead(200, { 'Content-Type': 'application/json; charset=utf-8' });
  res.end(JSON.stringify(list));
}
```

每个版本对象携带 `ts`（时间戳字符串）和 `current`（布尔值，标记是否为当前版本）。这个端点被前端 SPA 用于异步获取版本列表（当前未使用，但为未来扩展保留）。[来源](src/commands/browse.ts#L66-L73)

## buildVersionsHtml：版本列表渲染

```ts
function buildVersionsHtml(versions: string[], current: string): string {
  return versions.map(v =>
    `<a href="#" class="${v === current ? 'current' : ''}"
        onclick="switchVersion('${v}')">${v}</a>`
  ).join('');
}
```

- 当前版本获得 `class="current"`，在 CSS 中被渲染为 `color: #58a6ff; background: #1c2333; font-weight: 600;` — 蓝色高亮背景加粗。
- 其他版本渲染为默认颜色 `color: #8b949e`。
- 点击后调用 `switchVersion(ts)` 全局函数。[来源](src/commands/browse.ts#L352-L357)

## 版本切换 overlay：显示/隐藏逻辑

版本列表不直接显示在页面上，而是通过一个覆盖层（overlay）交互。UI 在 `serveHtml` 返回的 HTML 模板中定义：

```html
<div class="overlay" id="versionOverlay"
     onclick="if(event.target===this)hideVersions()">
  <div class="overlay-box">
    <span class="close-btn" onclick="hideVersions()">✕</span>
    <h3>历史版本</h3>
    <!-- versionsHtml 注入点 -->
    ${versionsHtml}
  </div>
</div>
```

三个 JavaScript 函数控制 overlay 生命周期：

```js
function switchVersion(ts) {
  window.location.href = '/?version=' + ts;
}

function showVersions() {
  document.getElementById('versionOverlay').classList.add('show');
}

function hideVersions() {
  document.getElementById('versionOverlay').classList.remove('show');
}
```

- **显示** — 点击侧栏顶部的"历史版本"按钮触发 `showVersions()`，为 overlay 添加 `show` 类，CSS 将 `display: none` 切换为 `display: flex`
- **隐藏** — 三种关闭方式：点击 overlay 的关闭按钮 ✕、点击 overlay 遮罩背景（`if (event.target===this)` 确保只响应直接点击遮罩而非内部盒子）、按键盘 Escape 键
- **切换版本** — `switchVersion(ts)` 执行全页面跳转 `window.location.href = '/?version=' + ts`，因为不同版本可能对应不同的侧栏结构和首页内容。这是一种**非 SPA 的版本切换**策略——为了简单可靠，直接走完整页面刷新。[来源](src/commands/browse.ts#L400-L437)

overlay 的 CSS 关键属性：

```css
.overlay { display: none; position: fixed; top: 0; left: 0;
           width: 100%; height: 100%; background: rgba(0,0,0,0.6);
           z-index: 100; justify-content: center; align-items: center; }
.overlay.show { display: flex; }
```

`fixed` 定位铺满全屏，半透明黑色背景（`rgba(0,0,0,0.6)`），flex 居中内部 `.overlay-box`。[来源](src/commands/browse.ts#L388-L393)
