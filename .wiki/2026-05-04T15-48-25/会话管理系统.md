# 会话管理系统

AI 问答模式允许多轮连续对话，每一次对话都是一个 **会话（Session）**。会话管理系统负责会话的创建、持久化、查询、恢复和删除，让用户可以在不同对话上下文之间自由切换，而不会丢失历史消息。

## Session 接口

所有会话数据由 `Session` 接口定义：

```typescript
export interface Session {
  id: string;
  created: string;
  updated: string;
  summary: string;
  messages: ChatMessage[];
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `string` | 8 位十六进制标识符 |
| `created` | `string` | ISO 8601 创建时间戳 |
| `updated` | `string` | ISO 8601 最后更新戳 |
| `summary` | `string` | 会话摘要（默认 `'新会话'`） |
| `messages` | `ChatMessage[]` | 完整的消息历史 |

其中 `messages` 数组的每个元素是 `ChatMessage` 类型，包含 `role`（system/user/assistant/tool）、`content`、`tool_calls` 等字段，与 [LLM 客户端设计的流式通信](llm-客户端设计与流式通信.md) 中的消息格式完全一致。[来源](src/ai/ai-session.ts#L6-L12) | [来源](src/ai/llm-client.ts#L5-L12)

## 持久化存储

每个会话独立存储为一个 JSON 文件，目录固定为项目工作目录下的 `.wiki/sessions/`：

```
.wiki/sessions/
├── a1b2c3d4.json
├── e5f6g7h8.json
└── ...
```

文件名称规则为 `{id}.json`，路径由工具函数 `sessionPath(id)` 生成：

```typescript
export function sessionPath(id: string): string {
  return join(SESSIONS_DIR, `${id}.json`);
}
```

`ensureSessionsDir()` 在首次写入前检查并创建目录，使用 `mkdir` 的 `recursive: true` 确保父目录一并创建。[来源](src/ai/ai-session.ts#L14-L18)

## CRUD 操作

### 创建会话 — `createSession()`

新会话的 ID 通过 `randomUUID().slice(0, 8)` 生成，取 UUID v4 的前 8 位字符作为简洁标识符。创建时同时写入 `created` 和 `updated` 字段为当前时间戳，`summary` 设置为 `'新会话'`，`messages` 为空数组。文件立即落盘。[来源](src/ai/ai-session.ts#L29-L37)

### 加载会话 — `loadSession(id)`

读取文件后执行 `JSON.parse`。整个操作包裹在 try-catch 中，任何异常（文件不存在、JSON 解析失败等）都返回 `null`，调用方据此判断会话是否存在或已损坏。[来源](src/ai/ai-session.ts#L59-L65)

### 列出会话 — `listSessions()`

扫描 `.wiki/sessions/` 目录下所有 `.json` 文件，逐个读取并解析。解析失败的条目会被静默跳过（`/* skip corrupt */`）。返回的列表按 `updated` 字段**降序排序**（最近更新的排在最前），每个条目仅包含 `id`、`created`、`updated`、`summary` 四个字段，避免加载完整消息历史。[来源](src/ai/ai-session.ts#L39-L57)

### 保存会话 — `saveSession(session)`

保存前强制更新 `session.updated` 为当前时间戳，然后序列化整个 `Session` 对象写入 JSON 文件。先调用 `ensureSessionsDir()` 确保目录存在。[来源](src/ai/ai-session.ts#L67-L72)

### 删除会话 — `deleteSession(id)`

检查文件是否存在，若存在则调用 `rm()` 删除，返回 `true`；文件不存在返回 `false`。[来源](src/ai/ai-session.ts#L74-L79)

## 显示逻辑

两个纯函数负责将会话数据渲染到终端，它们不涉及异步 I/O，仅做格式化输出。

### `printSession(session)`

遍历会话的 `messages` 数组：

- **用户消息**（`role === 'user'`）：以绿色 `You >` 前缀输出消息内容。但如果消息内容以 `/` 开头（即斜杠命令），则**跳过不显示**，避免在恢复会话时把 `/help`、`/sessions` 等系统内部命令暴露给用户。
- **助手消息**（`role === 'assistant'`）：直接输出内容，不加任何前缀。
- **system 和 tool 消息**：不输出。

这个函数在恢复历史会话时被调用，让用户看到之前的问答记录。[来源](src/ai/ai-session.ts#L81-L91) | [来源](src/commands/ai.ts#L168)

### `showSessionsTable(sessions)`

在 `wiki-cli ai --list-sessions` 或交互模式中的 `/sessions` 命令下触发。逻辑分两步：

1. **空列表**：输出 `(无保存的会话)`。
2. **有数据**：逐行打印，每行包含三个列——会话 ID、更新时间（`zh-CN` 本地化格式，显示月/日 时:分）、摘要（截取前 40 个字符）。

```text
📋 保存的会话:
  a1b2c3d4  12/15 14:30  新会话
  e5f6g7h8  12/14 09:15  如何配置自定义模型
```

列之间以两个空格分隔，无需对齐表头。[来源](src/ai/ai-session.ts#L93-L102) | [来源](src/commands/ai.ts#L52)

## 集成到 AI 问答命令

会话管理是 [AI 问答命令详解](ai-问答命令详解.md) 的底层基础设施。`aiCommand` 函数在启动时根据 `--session` 参数决定是创建新会话还是恢复已有会话，在每次问答后调用 `saveSession` 持久化最新消息，并将首个用户问题的前 60 字符设为 `summary`。[来源](src/commands/ai.ts#L155-L168)
