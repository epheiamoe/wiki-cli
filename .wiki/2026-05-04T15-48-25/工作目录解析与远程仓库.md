# 工作目录解析与远程仓库

每个 `wiki-cli` 命令在运行核心逻辑之前，都必须先回答一个问题："代码在哪里？" 答案由 `resolveWorkDir` 函数统一裁决，它根据 `url` 参数的存在与否，走两条截然不同的路径。[来源](src/utils/workspace.ts#L30-L89)

## 入口：一条 `if (url)` 的分岔口

`resolveWorkDir` 接收一个包含六个可选字段的参数对象，返回 `WorkDirResult`：

```typescript
interface WorkDirResult {
  workDir: string;       // 最终确定的工作目录
  outputDir?: string;    // 本地模式下可选的输出目录
  updated?: boolean;     // 远程仓库是否已更新（仅 URL 模式）
  cleanup?: () => Promise<void>;  // 临时模式的清理函数
}
```

[来源](src/utils/workspace.ts#L8-L13)

函数的逻辑主干是一个简单的 `if (url)` 判断——有 URL 走**远程克隆路径**，无 URL 走**本地目录路径**。两条路径最终都会执行 `process.chdir()` 切换当前工作目录，确保后续所有文件操作在正确的上下文中执行。[来源](src/utils/workspace.ts#L35-L89)

### 远程克隆路径（`url` 存在）

当提供 `--url` 时，目标目录由三个互斥条件决定，优先级从高到低为：

| 条件 | 目标目录 | 目录创建方式 |
|------|----------|-------------|
| `temp: true` | `os.tmpdir()/wiki-cli-XXXXXX` | `mkdtempSync` 生成唯一临时目录 |
| `output` 已提供 | `resolve(output)` | `mkdir` 递归创建 |
| 默认（两者皆无） | `~/.wiki-cli/repos/<url-dir>` | `mkdir` 递归创建 `REPOS_DIR` |

[来源](src/utils/workspace.ts#L37-L53)

确定 `targetDir` 后，调用 `ensureRepo(url, targetDir, branch, depth)` 执行 Git 操作。克隆/更新完成后执行 `process.chdir(targetDir)`。如果是 `--temp` 模式，返回的 `cleanup` 函数通过动态导入 `node:fs/promises` 的 `rm` 来删除临时目录树——延迟加载避免了非临时场景下不必要的模块引入。[来源](src/utils/workspace.ts#L55-L68)

### 本地目录路径（无 `url`）

没有 `--url` 时，使用 `dir` 参数（即 CLI 的 `-C`）或回退到 `process.cwd()`。这里有一个**硬性校验**：如果解析出的路径在文件系统中不存在，直接抛出 `Error` 终止流程。这区别于远程路径——克隆路径会在 `ensureRepo` 中自动创建目标目录。[来源](src/utils/workspace.ts#L71-L89)

本地路径下也支持 `--branch` 参数：如果有指定，调用 `git checkout <branch>` 切换分支。如果切换失败（分支不存在或根本不是 Git 仓库），打印错误并 `process.exit(1)`。[来源](src/utils/workspace.ts#L73-L81)

## `ensureRepo`：三种更新策略

`ensureRepo(url, targetDir, branch?, depth?)` 是 Git 操作的单一入口，返回 `{ updated: boolean }`。它的决策树基于 **目标目录是否存在** 和 **网络是否可达** 两个条件。[来源](src/utils/git.ts#L9-L32)

```
                    ┌─ 目录不存在 → git clone [--depth] [--branch]
                    │
ensureRepo 入口 ───┤                      ┌─ git fetch --all 成功
                    │                    │      ├─ 有 branch → checkout + merge origin/branch
                    └─ 目录已存在 ───┤      └─ 无 branch → merge
                                      │
                                      └─ git fetch 失败 → 返回 { updated: false } 降级使用缓存
```

**场景一：全新克隆**。当 `targetDir` 不存在时，构造 `git clone` 命令。`depthFlag` 和 `branchFlag` 按需拼接到命令字符串中，通过 `replace(/\s+/g, ' ').trim()` 归一化避免空标志的多余空格。克隆使用 `stdio: 'inherit'` 将进度直接透传给终端。失败则抛出 `Error`。[来源](src/utils/git.ts#L25-L32)

**场景二：增量更新**。当 `targetDir` 已存在，执行三步操作：(1) `git fetch --all` 拉取远程引用，(2) 若指定 `branch` 则 `git checkout` 切换，(3) `git merge origin/<branch>` 或默认 `git merge` 合并。三步全部成功才返回 `{ updated: true }`。[来源](src/utils/git.ts#L12-L21)

**场景三：网络降级**。如果 `git fetch` 本身失败（网络不可用），捕获异常后仅打印警告 `Network unavailable, using cached repo...`，静默返回 `{ updated: false }`。调用方据此知道仓库是旧版本，但**不中断流程**——缓存中的代码仍然可用。这种设计让 `generate` 和 `ai` 命令在离线环境下仍能正常工作。[来源](src/utils/git.ts#L22-L24)

## `urlToDirName`：URL → 目录名的规范化映射

`urlToDirName` 是一个纯字符串变换函数，将 Git URL 映射为文件系统友好的目录名。它依次执行三个正则替换：[来源](src/utils/workspace.ts#L16-L20)

| 步骤 | 正则 | 输入 | 输出 |
|------|------|------|------|
| 去掉协议 | `replace(/^https?:\/\//, '')` | `https://github.com/user/proj.git` | `github.com/user/proj.git` |
| 去掉 `.git` | `replace(/\.git$/, '')` | `github.com/user/proj.git` | `github.com/user/proj` |
| 分隔符替换 | `replace(/[\/:]/g, '-')` | `github.com/user/proj` | `github.com-user-proj` |

三个变换按先后顺序执行：先剥离协议前缀，再移除 `.git` 后缀，最后将路径分隔符统一替换为 `-`。结果作为持久缓存目录的子目录名。

`defaultRepoDir(url)` 将规范化后的名称拼接到 `~/.wiki-cli/repos/` 之下，形成完整的缓存路径。这个常量定义在模块顶部：[来源](src/utils/workspace.ts#L22-L28)

```typescript
const REPOS_DIR = join(homedir(), '.wiki-cli', 'repos');

export function defaultRepoDir(url: string): string {
  return join(REPOS_DIR, urlToDirName(url));
}
```

[来源](src/utils/workspace.ts#L15-L28)

## 三个命令的消费方式

`resolveWorkDir` 被三个命令共享，但各自的消费方式略有不同：

- **[生成命令详解](生成命令详解.md)**：检查 `updated === false` 时，若已有 `.wiki` 目录，询问用户是否重新生成以决定是否覆盖缓存。[来源](src/commands/generate.ts#L42-L60)
- **[AI 问答命令详解](ai-问答命令详解.md)**：仅获取 `cleanup` 函数，在会话结束后清理临时目录。实际问答路径由 `process.chdir` 切换后的 `workDir` 决定。[来源](src/commands/ai.ts#L34-L38)
- **[浏览命令详解](浏览命令详解.md)**：单独调用 `defaultRepoDir(url)` 定位已有缓存，不触发 `resolveWorkDir` 的完整流程，无需克隆或更新——浏览只读取已生成的 `.wiki` 静态文件。[来源](src/commands/browse.ts#L30)

这种设计体现了**关注点分离**：`resolveWorkDir` / `ensureRepo` 只负责"把代码放到正确目录并切换进去"，至于拿这些代码做什么（生成 Wiki、AI 问答、还是浏览），由各命令自行决定。
