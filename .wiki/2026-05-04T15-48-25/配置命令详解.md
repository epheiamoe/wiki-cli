# 配置命令详解

`wiki-cli config` 不是一条单功能命令——它管理着三套独立的配置体系。理解这三套配置的区别与关联，是流畅使用 wiki-cli 的关键。

## 三套配置体系一览

工具依赖三种外部服务，每种都需要独立配置：

| 配置体系 | 用途 | 不配置会怎样 | 配置入口 |
|---------|------|------------|---------|
| **LLM** | 驱动文档生成的"引擎"——所有大纲和页面内容都由它生成 | 无法运行 `generate` 和 `ai` | `wiki-cli config` 或直接传参 |
| **Embedding** | 为 Wiki 页面生成向量索引，实现语义搜索 | `ai` 命令的语义搜索不可用，退化为关键词搜索 | 交互式向导中选 "Embedding" |
| **Web Fetch** | 允许 LLM 读取外部文档 URL（通过 Jina Reader） | `generate` 和 `ai` 无法解析网络链接 | 交互式向导中选 "Web Fetch" |

同一个配置文件中同时保存这三套信息，互不干扰。交互式向导会依次询问你要配置哪一套，你也可以用 `--llm-only` 或 `--embedding-only` 跳过选择步骤。

[来源](src/commands/config.ts#L29-L67)

## LLM 配置

LLM 配置是整个工具的基础。它决定了文档生成使用哪个大模型、连接到哪个 API 端点、以及使用什么密钥。

### 交互式模式

运行 `wiki-cli config` 后，选择 "LLM" 或 "Both"，工具会引导你完成以下步骤：

1. **选择提供商** —— 从内置列表中挑选，或选 "Custom" 手动输入
2. **选择模型** —— 在选定提供商下挑选具体模型（每条模型附带价格提示）
3. **输入 API Key** —— 密码输入，用 `*` 掩码显示
4. **确认 JSON 模式** —— 自定义提供商时会询问是否支持

每一步都有默认值预填（如果之前已有配置），直接回车即可沿用。

[来源](src/commands/config.ts#L34-L51)

### 命令行模式（无交互）

如果你已清楚要使用哪个模型，一条命令就能完成 LLM 配置：

```bash
wiki-cli config --provider OpenAI --base-url https://api.openai.com/v1 --model gpt-5.4 --api-key sk-xxxx
```

当 `--provider`、`--base-url`、`--model`、`--api-key` 四个参数**同时提供**时，工具直接保存配置并退出，绝不弹出任何交互界面。可选参数 `--lang` 和 `--json-mode` 也在此模式下生效。

[来源](src/commands/config.ts#L12-L21)

### 内置的 8 个提供商

LLM 配置内置了以下 7 个提供商（外加 Custom 选项），共 21 个预注册模型：

| 提供商 | 预注册模型数 | 典型模型 | API 基地址 |
|--------|------------|---------|-----------|
| **OpenAI** | 5 | gpt-5.5, gpt-5.4, gpt-5.4-mini | `https://api.openai.com/v1` |
| **Google Gemini** | 3 | gemini-3.1-pro, gemini-3-flash | `https://generativelanguage.googleapis.com/v1beta` |
| **Anthropic** | 3 | claude-opus-4-7, claude-sonnet-4-6 | `https://api.anthropic.com/v1` |
| **xAI Grok** | 3 | grok-4.3, grok-4.20-reasoning | `https://api.x.ai/v1` |
| **DeepSeek** | 2 | deepseek-v4-pro, deepseek-v4-flash | `https://api.deepseek.com` |
| **Kimi (Moonshot)** | 2 | kimi-k2.6, kimi-k2.5 | `https://api.moonshot.cn/v1` |
| **Mistral** | 3 | mistral-large-3, ministral-14b | `https://api.mistral.ai/v1` |
| **Custom** | — | 手动输入任意模型名 | 手动输入任意 URL |

完整模型清单见 [default-models.json](src/config/default-models.json)。

### JSON 模式兼容性

生成管线要求 LLM 以结构化 JSON 格式返回内容（用于解析大纲和页面字段）。不同提供商对该能力的支持不同，配置时自动判断：

| 提供商 | 支持 JSON 模式？ | 配置时的处理 |
|--------|---------------|------------|
| OpenAI | ✅ 是 | 自动启用，用户无感知 |
| DeepSeek | ✅ 是 | 同上 |
| xAI Grok | ✅ 是 | 同上 |
| Mistral | ✅ 是 | 同上 |
| Kimi (Moonshot) | ✅ 是 | 同上 |
| Google Gemini | ❌ 否 | 自动禁用，用户无感知 |
| Anthropic | ❌ 否 | 自动禁用，用户无感知 |
| Custom | ❓ 未知 | 弹出确认问题让用户手动选择 |

这个判断逻辑实现在 `supportsJsonMode()` 函数中，核心是一个硬编码的 Set：

```typescript
const JSON_MODE_PROVIDERS = new Set([
  'OpenAI', 'DeepSeek', 'xAI Grok', 'Mistral', 'Kimi (Moonshot)',
]);
```

当提供商为 `'Custom'` 时返回 `undefined`，触发交互式询问；其余情况直接返回 `Set.has(provider)` 的结果。

## Embedding 配置

Embedding 配置为 [AI 问答命令详解](ai-交互命令-wiki-cli-ai.md) 中的语义搜索功能提供向量计算能力。它是可选的，不配置也能使用 `ai` 命令（退化为关键词匹配）。

### 交互式流程

在配置向导中选择 "Embedding" 或 "Both" 后，流程如下：

1. **是否启用？** —— 确认是否配置 Embedding。如果不启用，所有 Embedding 字段会被清空
2. **选择提供商** —— 从内置列表或 "Custom"
3. **选择模型** —— 每个模型附带 `dimensions`（向量维度）和价格提示
4. **输入 API Key** —— 留空则复用 LLM 的 API Key

关键设计：**API Key 为空时自动使用 LLM 的密钥**，这意味着如果 Embedding 提供商和 LLM 提供商相同（如都用 OpenAI），你无需重复输入。

[来源](src/commands/config.ts#L91-L132)

## Web Fetch 配置

Web Fetch 允许 LLM 在生成文档或回答问题时读取外部 URL 的内容（基于 Jina Reader API）。这也是可选功能，不在配置中启用则 LLM 无法访问网络链接。

### 交互式流程

在向导中选择 "Web Fetch" 后，流程极为简洁——因为 Web Fetch 通常不需要频繁切换提供商：

1. **是否启用？** —— 确认是否开启 Web Fetch
2. **提供商名称** —— 默认 `jina`，可改为任意字符串
3. **Base URL** —— 默认 `https://r.jina.ai`
4. **API Key**（可选）—— 留空使用免费层，填写可获得更高速率限制

如果选择不启用，`webFetchDisabled` 被设为 `true`，同时清空其他 Web Fetch 字段。

[来源](src/commands/config.ts#L134-L165)

### 参数说明

| 参数 | 默认值 | 说明 |
|------|-------|------|
| `webFetchProvider` | `'jina'` | 服务提供商标识 |
| `webFetchBaseUrl` | `'https://r.jina.ai'` | API 端点地址 |
| `webFetchApiKey` | `undefined` | 可选，用于提高速率限制 |

Web Fetch 在生成管线中的具体用途参见 [工具系统：12 个只读工具](工具系统-llm-只读探索工具的设计.md)。

## 完整的命令行参数参考

`wiki-cli config` 支持以下参数，涵盖三套配置体系：

| 参数 | 类型 | 对应配置体系 | 说明 |
|------|------|------------|------|
| `--provider` | string | LLM | 提供商名称 |
| `--base-url` | string | LLM | API 基地址 |
| `--model` | string | LLM | 模型名称 |
| `--api-key` | string | LLM | API 密钥 |
| `--lang` | string | LLM | 文档语言（zh/en，默认 zh） |
| `--json-mode` | boolean | LLM | 是否启用 JSON 输出模式 |
| `--llm-only` | boolean | — | 只配置 LLM，跳过其他 |
| `--embedding-only` | boolean | — | 只配置 Embedding，跳过其他 |

当 `--provider`、`--base-url`、`--model`、`--api-key` 全部提供时进入**静默模式**，跳过全部交互。否则根据 `--llm-only`/`--embedding-only` 决定进入哪个交互分支，默认弹出模式选择菜单。

## 配置持久化：~/.wiki-cli/config.json

所有配置最终保存到用户主目录下的统一 JSON 文件：

```
~/.wiki-cli/config.json
```

在 Windows 上，`~` 对应 `C:\Users\<用户名>\`；在 macOS/Linux 上对应 `/home/<用户名>/`。

### 完整的存储结构

```json
{
  "provider": "OpenAI",
  "baseUrl": "https://api.openai.com/v1",
  "model": "gpt-5.4",
  "apiKey": "sk-xxxx",
  "lang": "zh",
  "jsonMode": true,
  "embeddingProvider": "OpenAI",
  "embeddingModel": "text-embedding-3-small",
  "embeddingBaseUrl": "https://api.openai.com/v1",
  "embeddingApiKey": "sk-xxxx",
  "webFetchDisabled": false,
  "webFetchProvider": "jina",
  "webFetchBaseUrl": "https://r.jina.ai",
  "webFetchApiKey": ""
}
```

### 字段与类型定义

该结构由 `WikiCliConfig` 接口定义：

| 字段 | 类型 | 必填 | 所属体系 | 说明 |
|------|------|------|---------|------|
| `provider` | string | ✅ | LLM | 提供商名称 |
| `baseUrl` | string | ✅ | LLM | API 基地址 |
| `model` | string | ✅ | LLM | 模型名称 |
| `apiKey` | string | ✅ | LLM | API 密钥 |
| `lang` | string | ✅ | LLM | 文档语言，默认 `'zh'` |
| `jsonMode` | boolean | ❌ | LLM | JSON 输出模式，自动推断或用户确认 |
| `embeddingProvider` | string | ❌ | Embedding | Embedding 提供商 |
| `embeddingModel` | string | ❌ | Embedding | Embedding 模型 |
| `embeddingBaseUrl` | string | ❌ | Embedding | Embedding API 地址 |
| `embeddingApiKey` | string | ❌ | Embedding | Embedding API 密钥，为空则复用 `apiKey` |
| `webFetchDisabled` | boolean | ❌ | Web Fetch | 是否禁用 Web Fetch |
| `webFetchProvider` | string | ❌ | Web Fetch | Web Fetch 提供商 |
| `webFetchBaseUrl` | string | ❌ | Web Fetch | Web Fetch API 地址 |
| `webFetchApiKey` | string | ❌ | Web Fetch | Web Fetch API 密钥（可选） |

注意 Embedding 的 API Key 有一个特例逻辑：如果用户留空，运行时自动使用 LLM 的 `apiKey`。

[来源](src/config/config-store.ts#L4-L16)

### 读写机制

保存时，工具自动创建 `~/.wiki-cli` 目录（如果不存在），然后以 UTF-8 格式写入 `config.json`，缩进 2 个空格：

```typescript
export async function saveConfig(config: WikiCliConfig): Promise<void> {
  await mkdir(CONFIG_DIR, { recursive: true });
  await writeFile(CONFIG_PATH, JSON.stringify(config, null, 2), 'utf-8');
}
```

读取时，如果文件不存在或解析失败，返回 `null`，触发首次配置向导：

```typescript
export async function loadConfig(): Promise<WikiCliConfig | null> {
  if (!existsSync(CONFIG_PATH)) return null;
  const raw = await readFile(CONFIG_PATH, 'utf-8');
  return JSON.parse(raw) as WikiCliConfig;
}
```

## 推荐的配置顺序

1. **先配 LLM** —— 这是核心，不配 LLM 什么也做不了
2. **按需配 Embedding** —— 如果计划使用 `ai` 命令的语义搜索功能
3. **按需配 Web Fetch** —— 如果生成文档时需要 LLM 读取外部链接

配置完成后，头也不回地进入 [快速开始](快速开始.md) 跑通完整流程。
