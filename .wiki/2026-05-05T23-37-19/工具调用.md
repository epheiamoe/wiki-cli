# 工具调用

如果你曾在 AI 聊天界面中点过"查看代码"按钮，就会明白"工具"的直觉含义：让 AI 不只靠自身知识回答，还能**真实地读取你的代码**。`tool-call` 命令就是把这种能力暴露为 **Shell 接口**，供任何外部 Agent 使用——不限于内置的 `ai` 聊天，任何能执行 CLI 命令的程序都可以调用它。

## 设计定位：Agent 的"眼睛"

wiki-cli 的 `tool-call` 是一个**只读接口**。它不做任何写入操作（不修改文件、不提交 Git、不更改配置），只负责：

- 读取目录结构
- 搜索文件内容
- 查询 Git 历史
- 检索 Wiki 页面
- 抓取网页文档

这种"只读"约束让 AI Agent 可以安全地使用这些工具，无需担心产生副作用。[来源](src/commands/tool-call.ts#L1-L22)

## 命令用法

`tool-call` 接收两个参数：工具名称和可选的 JSON 参数字符串。

```bash
wiki-cli tool-call <name> [args]
```

实际示例：

```bash
# 列出目录结构（深度 2）
wiki-cli tool-call list_directory '{"dir_path": ".", "max_depth": 2}'

# 读取文件（行号会自动前缀）
wiki-cli tool-call read_file '{"file_path": "src/cli.ts"}'

# 搜索字符串
wiki-cli tool-call search_in_files '{"path": "src", "pattern": "embedding"}'

# 无参数工具
wiki-cli tool-call git_remote_info
```

参数 `args` 必须是合法的 JSON 字符串。如果省略，工具将使用空对象 `{}`。[来源](src/cli.ts#L150-L162)

## 统一输出格式

所有工具返回**完全一致的 JSON 结构**：

```typescript
interface ToolResult {
  type: 'success' | 'error';
  data: any;
}
```

| 字段 | 含义 |
|------|------|
| `type` | `"success"` 表示正常返回，`"error"` 表示出错 |
| `data` | 成功时是工具的结果数据，失败时是错误消息字符串 |

成功示例（`git_remote_info` 返回结构化数据）：

```json
{"type":"success","data":[{"name":"origin","url":"https://github.com/user/repo.git","type":"fetch"}]}
```

失败示例：

```json
{"type":"error","data":"File not found: nonexistent.txt"}
```

控制台输出直接写入 `stdout`，由 `console.log(JSON.stringify(result))` 完成，方便 Agent 直接解析。[来源](src/commands/tool-call.ts#L43-L45)

## 13 个工具一览

所有工具的定义集中管理在 `src/ai/tools.ts` 的 `toolDefinitions` 数组中。[来源](src/ai/tools.ts#L20-L207)

### 文件系统类（4 个）

| 工具 | 用途 | 必填参数 | 可选参数 |
|------|------|----------|----------|
| `list_directory` | 获取目录结构树 | `dir_path` | `max_depth`（默认 3） |
| `list_files` | 列出目录下所有文件路径 | `path` | `extensions`（按后缀过滤） |
| `read_file` | 读取文件内容，每行前缀行号 | `file_path` | `start_line`、`end_line`（行范围） |
| `search_in_files` | 在文件中搜索关键词/正则 | `path`、`pattern` | `extensions`（范围过滤） |

**`read_file` 的三大特性**：

1. **行号前缀**：输出中每行以 `行号: 内容` 格式呈现，让 Agent 精确定位代码位置。[来源](src/ai/tools.ts#L303)
2. **行范围截取**：通过 `start_line`（1-indexed）和 `end_line` 参数，只读取文件的某一段。[来源](src/ai/tools.ts#L293-L300)
3. **超长自动截断**：当输出超过 30,000 字符时自动截断，并在末尾附加详细提示——包含文件总大小、总行数、当前显示的行范围，以及继续读取的 `start_line` 建议值。[来源](src/ai/tools.ts#L306-L314)

### Git 类（3 个）

| 工具 | 用途 | 必填参数 | 可选参数 |
|------|------|----------|----------|
| `git_log` | 获取提交历史 | 无 | `max_count`（默认 20）、`path`（按文件过滤） |
| `git_show` | 查看某个 Git 对象详情 | `object`（commit hash / branch 等） | `path`（指定仓库内文件路径） |
| `git_remote_info` | 获取远程仓库信息 | 无 | 无 |

`git_remote_info` 的返回结果不再是原始字符串，而是解析后的结构化数组：每个远程仓库包含 `name`、`url`、`type` 三个字段。[来源](src/ai/tools.ts#L387-L399)

这三个工具通过 `execSync` 调用系统的 `git` 命令，在项目根目录下执行。[来源](src/ai/tools.ts#L362-L399)

### Wiki 类（3 个）

| 工具 | 用途 | 必填参数 | 可选参数 |
|------|------|----------|----------|
| `list_wiki_pages` | 列出所有 Wiki 页面及其元信息 | 无 | 无 |
| `read_wiki` | 按 slug 读取 Wiki 页面内容 | `slug` | 无 |
| `search_wiki` | 全文关键词搜索 Wiki，返回结构化结果 | `query` | `max_results`（默认 5） |

`list_wiki_pages` 优先读取 `.wiki/<版本>/index.json` 获取结构化索引，提取每个页面的 slug、标题、章节和难度等级。如果没有 index.json，则回退到扫描 `.md` 文件。[来源](src/ai/tools.ts#L430-L466)

`search_wiki` 返回的不是简单文件名列表，而是包含 `slug`、`title`、`snippet`（匹配上下文摘要）、`score` 的结构化结果，让 Agent 能直接判断相关度。[来源](src/ai/tools.ts#L512-L565)

`read_wiki` 支持**模糊匹配**：如果精确的 slug 找不到，会尝试在文件名中搜索包含关系。[来源](src/ai/tools.ts#L468-L493)

### 配置与环境类（2 个）

| 工具 | 用途 | 必填参数 | 可选参数 |
|------|------|----------|----------|
| `dotenv_template` | 读取 `.env.example` 模板 | 无 | 无 |
| `semantic_search` | 语义搜索 Wiki（基于 Embedding） | `query` | `max_results`（默认 5） |

`semantic_search` 仅在配置了 Embedding 模型时可用，否则返回错误提示。它调用 `embeddings.ts` 中的 `semanticSearch` 函数执行向量检索，返回结果包含 `slug`、`title`、`score`（归一化余弦相似度）。[来源](src/ai/tools.ts#L567-L610)

### 网络类（1 个）

| 工具 | 用途 | 必填参数 | 可选参数 |
|------|------|----------|----------|
| `fetch_web_markdown` | 抓取 URL 并转为干净 Markdown | `url` | 无 |

这个工具通过 `r.jina.ai`（或用户配置的 WebFetch Base URL）将网页转为 Markdown，请求时携带 `Accept: text/markdown` 头。内部包含**重试逻辑**：遇到 429（限流）或 5xx（服务端错误）时最多重试 3 次，使用指数退避策略。请求超时设置为 15 秒。[来源](src/ai/tools.ts#L612-L676)

## 运行前的初始化

每次调用 `tool-call` 命令时，`toolCallCommand` 函数会做三件事：

1. **加载配置**——通过 `loadConfig()` 读取用户配置，如果未配置则报错退出
2. **校验工具名**——在 `toolDefinitions` 中查找，如果找不到则列出所有可用工具并退出
3. **初始化工具环境**——调用 `initTools()` 传入 Embedding 配置、WebFetch 配置和当前工作目录

如果配置中未启用 Embedding，`semantic_search` 在运行时返回错误提示；如果禁用了 WebFetch（`webFetchDisabled: true`），`fetch_web_markdown` 不会出现在 AI 聊天的工具列表中——这是通过 `getFilteredTools()` 函数实现的，而非在 `tool-call` 命令层面过滤。[来源](src/commands/tool-call.ts#L5-L45)

## 执行调度机制

`toolDefinitions` 和 `toolHandlers` 是两个分离的注册表：

- `toolDefinitions` —— 描述工具的 Schema（名称、描述、参数结构），供 AI 理解"有哪些工具可用"
- `toolHandlers` —— 存储实际的执行函数，通过工具名做键值映射

`executeToolCall(name, args)` 函数充当调度中心：`let handler = toolHandlers[name]`，找到则调用，找不到返回错误。[来源](src/ai/tools.ts#L678-L700)

## 条件过滤：getFilteredTools()

`src/ai/tools.ts` 导出一个额外的函数 `getFilteredTools()`，它根据运行时配置动态决定哪些工具对 AI 可见：

- 如果 WebFetch 被禁用，从列表中移除 `fetch_web_markdown`
- 否则返回全部 13 个工具

这个函数在 [AI 问答](ai-问答.md)、[AI 聊天面板：浏览器内对话](ai-聊天面板-浏览器内对话.md) 和 [生成 Wiki](生成-wiki.md) 的 Tool-augmented 写作循环中被使用，而 `tool-call` 命令本身不做此过滤。[来源](src/ai/tools.ts#L505-L509)

## 在 AI 聊天中的应用

`tool-call` 命令是 [AI 问答](ai-问答.md) 系统的底层支撑。当你在聊天中问"这个项目的目录结构是什么"，AI 不会凭空猜测——它会在幕后执行 `wiki-cli tool-call list_directory`，把真实结果作为上下文来生成回答。

这种"Shell 接口即工具"的设计，让同一套工具既能在命令行手动调试，也能被 [AI 聊天面板：浏览器内对话](ai-聊天面板-浏览器内对话.md) 中的 SSE 流式调用所使用。[来源](src/commands/tool-call.ts#L1-L45)
