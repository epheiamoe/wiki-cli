# 查看状态

你的 Wiki 是基于代码仓库的某个版本生成的。但代码在不断演进——当你改了代码，Wiki 就过时了。`status` 命令就是用来回答"我的 Wiki 还新鲜吗？"这个问题的。

## 一句话概括

`status` 读取 Wiki 版本目录中保存的 `.meta.json`，取出其中的 `gitCommit` 字段（记录的是生成时仓库 HEAD 的提交哈希），然后用 `git rev-parse HEAD` 拿到当前仓库的最新提交，两者一比较，就知道 Wiki 是否落后于代码。

[来源](src/commands/status.ts#L52-L84)

## 它去哪儿找 Wiki？

status 按以下优先级查找 `.wiki` 目录：

| 参数 | 说明 |
|---|---|
| `-u, --url <url>` | 通过远程 URL 查找缓存的仓库目录下的 `.wiki` |
| `-C, --dir <path>` | 指定项目目录下的 `.wiki` |
| （不传） | 当前工作目录下的 `.wiki` |

找到 `.wiki` 后，它会列出所有版本子目录（排除 `temp` 和 `sessions`），按名称排序取最新的那个。你也可以用 `-v, --version <ts>` 指定一个具体的版本时间戳。

[来源](src/commands/status.ts#L23-L48)

## 四种状态

### ✅ 绿色——完全同步

当 `.meta.json` 中的 `gitCommit` 与当前 HEAD 完全一致时：

```
📖 Wiki: 20240101120000
   生成于:    2024-01-01T12:00:00.000Z
   基于提交:  a1b2c3d feat: add user authentication
   当前 HEAD: a1b2c3d feat: add user authentication
   状态:      ✅ Wiki 是最新的
```

这意味着你看到的就是基于当前代码生成的 Wiki，一个字都不差。

[来源](src/commands/status.ts#L97-L102)

### ⚠️ 黄色——已落后

当 gitCommit 与 HEAD 不同，且能够计算出差异 commit 数量时：

```
📖 Wiki: 20240101120000
   生成于:    2024-01-01T12:00:00.000Z
   基于提交:  a1b2c3d feat: add user authentication
   当前 HEAD: e5f6g7h fix: resolve login timeout
   落后:      3 commits
   状态:      ⚠ Wiki 已过时
```

这里 `git log --oneline a1b2c3d..HEAD` 统计了两个提交之间的 commit 数量，输出中写的就是"落后 N 个 commit"。

[来源](src/commands/status.ts#L104-L113)

### ⚡ 无元数据

如果版本目录中没有 `.meta.json` 文件，说明这个 Wiki 是用早期版本生成的，那时还没有元数据追踪功能：

```
📖 Wiki: 20240101120000
   生成于:    （无元数据）
   状态:      ⚡ 该版本生成时尚未启用元数据追踪
```

这是唯一无法比较的情况——不是出错了，只是"那时候没记录"。

[来源](src/commands/status.ts#L50-L56)

### ⚠ 其他异常

还有几种边界情况会显示警告信息：

- **meta.gitCommit 为空** → 显示"非 git 项目"
- **当前不在 git 仓库**（`git rev-parse HEAD` 失败）→ 显示"当前不在 git 仓库，无法比较"
- **记录的提交不存在**（经历了 rebase 或切换了远程仓库）→ 显示"提交记录不可用（可能经历了 rebase 或切换了 remote）"
- **提交不在当前历史中**（behindCount 为 -1）→ 显示"无法比较（提交不在当前历史中）"

[来源](src/commands/status.ts#L70-L95)

## 想看具体变更？用 `--log` 或 `--stat`

光知道"落后了 N 个 commit"不够，你还想知道改了哪些东西。这就是 `--log` 和 `--stat` 的作用：

```
wiki-cli status --log
```

会在落后状态下额外输出 `git log --oneline` 的结果，每一行一个 commit：

```
   ── 变更日志 ──
   e5f6g7h fix: resolve login timeout
   d4e5f6a refactor: extract auth middleware
   c3d4e5b feat: add rate limiting
```

而 `--stat` 则输出 `git log --stat` 的结果，会多显示每个 commit 修改了哪些文件、改了多少行：

```
wiki-cli status --stat
```

[来源](src/commands/status.ts#L118-L126)

## 选项速查

| 选项 | 作用 |
|---|---|
| `-v, --version <ts>` | 指定 Wiki 版本（默认取最新） |
| `-C, --dir <path>` | 项目目录 |
| `-u, --url <url>` | Git 远程 URL（查找缓存的 Wiki） |
| `--log` | 显示落后 commit 的 oneline 日志 |
| `--stat` | 显示落后 commit 的 stat 详细日志 |

[来源](src/cli.ts#L88-L97)

## 与工作目录解析的关系

`status` 查找 `.wiki` 目录的逻辑复用了 [工作目录解析](工作目录解析.md) 中的 `findExistingRepoDir` 函数。当你使用 `-u` 参数时，它会在配置的缓存目录中寻找已经 clone 过的仓库，定位其下的 `.wiki`。你也可以参考 [生成 Wiki](生成-wiki.md) 了解 Wiki 是在何时创建这些元数据的。

[来源](src/commands/status.ts#L24-L27)
